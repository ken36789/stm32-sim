# 原始碼導讀

這份文件寫給想要讀懂、維護或擴充這個專案的開發者，例如要新增一塊開發板、一種外接模組或一個 SDK 函式。功能介紹與每個檔案的一行說明請看 [README.md](../README.md)，這裡不重複，而是說明各部分怎麼接在一起、資料怎麼流動，以及要擴充時該改哪些地方。

文中提到的檔案、函式、欄位與常數都以目前的原始碼為準，程式碼摘錄都是從原始碼原封不動複製的片段。給學習者看的範例 C 程式說明在 [程式解說.md](程式解說.md)。

## 1. 整體架構

### 技術組成

- 建置工具是 Vite 5。`vite.config.js` 設定 `base: './'`，註解寫明用意：產出的檔案都用相對路徑，放在網域根目錄或 GitHub Pages 的子路徑（`/repo-name/`）都能用。
- 3D 用 three.js；網站裡顯示的說明文件（包括這一份）由 `src/ui/guide.js` 用 `marked` 轉成 HTML。除此之外沒有任何框架，全部是原生 ES 模組。
- 沒有後端。所有狀態都在瀏覽器的記憶體與 `localStorage` 裡。

### 分層與相依方向

| 位置 | 負責 | 可以 import |
| --- | --- | --- |
| `src/core/` | 模擬核心：開發板與模組資料、接線與電氣網路、接線檢測、範例程式產生、C 編譯與執行、匯流排、邏輯分析儀、步進馬達、闖關判定 | 只有 `src/core/` 自己 |
| `src/scene/` | three.js 畫面：`scene.js`（場景、開發板、電源軌、杜邦線、視角）、`modules3d.js`（模組外觀與狀態顯示） | `three`、`src/core/` |
| `src/ui/` | DOM 面板：元件分頁、編輯器、序列埠、建置與燒錄、邏輯分析儀視窗、示波器、闖關卡片、說明文件 | `src/core/`、`src/config.js`、同一層，以及 `marked` |
| `src/main.js` | 進入點：把核心、3D 與面板接起來，負責實驗流程、動畫迴圈與存檔 | 全部 |

```text
index.html                  啟動保護腳本，然後載入 src/main.js
  └─ src/main.js            填入 hooks、實驗流程、ACTIONS、動畫迴圈、存檔
       ├─ src/ui/*.js       DOM 面板
       │    └─ src/core/*.js
       ├─ src/scene/*.js    three.js 畫面
       │    └─ src/core/*.js
       ├─ src/config.js     選用的統計與報名表設定
       └─ src/core/*.js     模擬核心：不 import DOM、three.js、ui、scene
            └─ hooks.js     核心往外通知的出口，預設全部是 noop
```

上層 import 下層，`src/ui/` 與 `src/scene/` 彼此不 import，`src/core/` 從不 import 上層，所以可以直接在 Node 裡測試（`tests/core.test.js`）。`scene.js` 和 `modules3d.js` 彼此 import（`buildBench()` 呼叫 `buildModule()`，`modules3d.js` 用 `scene.js` 的建模小工具）。

### hooks.js：核心與介面之間的接點

`hooks.js` 開頭的註解寫明：核心只呼叫 hooks，介面在啟動時把實作填進來。核心需要通知外面（多了一條線、序列埠有輸出、執行狀態改變）時，就呼叫這些函式：

```js
export const hooks = {
  toast: noop,          // (訊息, 'err'?) 顯示提示
  afterWiring: noop,    // 接線變動後
  wireAdded: noop,      // (wire) 新增一條線
  wireRemoved: noop,    // (wire) 移除一條線
  outputs: noop,        // GPIO 輸出改變
  serial: noop,         // (字串) printf / UART 輸出
  sys: noop,            // (訊息, class?) 模擬器系統訊息
  run: noop,            // (狀態) 執行狀態改變：idle/flash/run/halt/fault/done/off/reset
  sensorDamaged: noop,  // (boolean) 感測器損壞狀態
  recheck: noop,        // 重新執行接線檢測
  benchChanged: noop,   // 開發板或模組變更（需要重建 3D 與面板）
  analyzed: noop,       // ({ m, proto, opt, res }) 邏輯分析儀完成一次解碼（闖關判定用）
  stepperOpened: noop,  // (模組) 打開步進馬達示波器
};
```

- `main.js` 的 `wireHooks()` 在啟動時用 `Object.assign(hooks, {...})` 填入實作，例如 `wireAdded` 會呼叫 `scene.js` 的 `buildWireMesh()`，`serial` 會呼叫 `serialOut()` 與 `learnSerial()`。
- 測試不需要介面，直接替換需要的那幾個，例如 `hooks.serial = s => { out += s; }` 收集序列埠輸出。
- 介面檔案也會用到 hooks：`ui/analyzer.js` 解碼後呼叫 `hooks.analyzed`，`main.js` 把它接到 `ui/learn.js` 的 `learnAnalyzed()`。
- 另一種做法是把函式推進核心的監聽陣列：`ui/learn.js` 用 `pinListeners.push()` 在每次 GPIO 改變時計數（見 2.3）。
- `stepperOpened` 目前只有宣告，沒有任何地方呼叫或填入。

### 共用狀態是模組層級的單例

核心的狀態都放在模組層級的變數：`sim.js` 的 `SIM`、`bench`、`wires`、`PINS`、`NET`，`trace.js` 的 `TRACE`，`buses.js` 的 `CAN`，`steppers.js` 的 `PWM`，`runtime.js` 的 `RUN`。同一時間只有一個工作台。`wires`、`PINS`、`NET` 是 `export let`，`resetBench()`、`rebuildPins()`、`refreshNet()` 會整個換掉它們的值，其他檔案透過 ES 模組的即時繫結看到新值，所以不要自己另外保存一份參照。

## 2. 資料流程

先看兩條主要路徑，再逐一說明每個檔案。

```text
接線：使用者在 3D 畫面點兩個腳位
  main.js onPick() ─► sim.js addWire()
                        ├─► hooks.wireAdded   ─► scene.js buildWireMesh()
                        └─► hooks.afterWiring ─► main.js afterWiring()
                              ├─ refreshNet()：netMap() 重建 NET
                              ├─ hwSig() 改變 ─► hwChanged()：韌體標成需重新燒錄
                              ├─ electricalUpdate()：checkDamage()、powered()
                              ├─ doCheck(true)、refreshExample()、store()
                              └─ outputsChanged() ─► applyOutputs()
                                   └─ moduleState(m) ─► modules3d.js updateModule(m, s, t)

程式：① 檢測 ② 編譯 ③ 燒錄
  runChecks(src) ─► UI.checkOk
  build() ─► compile(src) ─► { js, size } ─► UI.built
  flash() ─► SIM.flashed = { js, size } ─► startProgram()
    new AsyncFunction(...API_NAMES, js)，傳入 makeAPI(r) 的每一個值
      GPIO 函式 ─► pinWrite() ─► SIM.out、traceGpio()、pinListeners ─► hooks.outputs()
      printf 類 ─► uartOut() ─► traceUART()、hooks.serial()
      I2C／SPI／CAN 函式 ─► buses.js ─► devices.js、spidev.js、CAN 測試節點
      計時器 PWM 函式 ─► steppers.js pwmSet()、pwmRun()
```

### 2.1 工作台狀態：sim.js

```js
export const SIM = { usb:true, flashed:null, out:{}, mode:{}, run:'idle', b1:false, ambient:{ T:24.6, RH:55 } };
export const bench = { board:BOARD_BY_ID[DEFAULT_BOARD], modules:[] };
export let PINS = {}, PIN_ORDER = [], NET = null;
export let wires = [];
```

- `SIM.usb`：USB 是否接上。`SIM.flashed`：燒錄進去的程式 `{ js, size }`，`main.js` 另外加上 `rev`（燒錄當時的版本號）與 `stale`（硬體改過、需要重新燒錄）。`SIM.out`、`SIM.mode`：每支 MCU 腳位的輸出值與方向（`'out'` 或 `'in'`）。`SIM.run`：執行狀態，值見 `hooks.run` 的註解，`main.js` 另外會設成 `'stale'`。`SIM.b1`：板載按鈕是否按下。`SIM.ambient`：環境溫度與溼度。
- `bench.modules` 的每一個元素是 `{ id:'M1', type, variant, slot, slot2?, st }`。`st` 由 `freshState()` 建立（按鈕狀態、旋鈕位置、損壞旗標等），執行時再按需要加上其他欄位：`dev`（I2C 元件模型，`sim.js`）、`sdev`、`csLow`、`node`（SPI 元件與 CAN 測試節點，`buses.js`）、`mem`、`wel`、`busyUntil`（Flash 內容與狀態，`spidev.js`）、`mot`、`drv`（`steppers.js` 的 `motorOf()`、`drvOf()`）。
- 工作台有 `MAX_MODULES`（12）格。`big` 的模組（驅動板）用 `slotPartner()` 佔前後相鄰的兩格，第二格記在 `slot2`。

`rebuildPins()` 依開發板、電源軌與模組建立 `PINS`（id 到腳位資料，含 `group`、`name`、`kind`、`label`、`func`）。腳位 id 和它在電氣網路裡的節點名稱由 `nodeOf()` 對應：

| 種類 | 腳位 id 例 | `nodeOf()` 的結果 |
| --- | --- | --- |
| 排針 GPIO | `J.D13`、`J.PB6` | MCU 腳位名稱，例如 `PA5` |
| 排針電源 | `J.3V3~1`、`J.5V~1` | `3V3`、`5V` |
| 排針地 | `J.GND~2` | `GND` |
| 電源軌 | `R.+1` 到 `R.+14`、`R.-1` 到 `R.-14` | `RAIL+`、`RAIL-` |
| 模組腳位 | `M3.SCL` | 原樣（`M3.SCL`） |

同一個標籤在排針上出現多次時，id 會加上 `~1`、`~2`。電源軌本身沒有接任何電源；用到電源軌時，要從排針拉線到 + 與 −，否則檢測會警告。

`addWire(a, b, color, quiet)` 依序拒絕：起點等於終點、已經接過的兩支腳、超過 `maxWires()`（排針與電源軌每孔 1 條，模組腳位 2 條，方便串接 I2C）、同一個模組的兩支腳互接（`tie` 例外，見 2.2）。通過後建立一條線，呼叫 `hooks.wireAdded`，`quiet` 為假時再呼叫 `hooks.afterWiring`。

### 2.2 電氣網路：netMap()

```js
export function netMap(){
  const parent = {};
  const f = k => { if (!(k in parent)) parent[k] = k; while (parent[k] !== k){ parent[k] = parent[parent[k]]; k = parent[k]; } return k; };
  const join = (x, y) => { const a = f(x), b = f(y); if (a !== b) parent[a] = b; };
  for (const w of wires) join(nodeOf(w.a), nodeOf(w.b));
  // 模組板上本來就相通的腳（例如驅動板左右兩側的 GND）
  for (const m of bench.modules) for (const [a, b] of MODULE_TYPES[m.type].bridge || []) join(`${m.id}.${a}`, `${m.id}.${b}`);
  const groups = {}; for (const k of Object.keys(parent)){ const r = f(k); (groups[r] = groups[r] || []).push(k); }
  return { f, groups };
}
```

- 這是 union-find（路徑減半）。節點是 `nodeOf()` 的結果，所以所有 GND 排針是同一個節點，所有電源軌 + 孔也是同一個節點。
- 模組種類的 `bridge` 列出板上本來就相通的腳（TB67S128FTG 的 `GND` 與 `PGND`），在所有杜邦線之後一起合併。
- `tie` 是 `addWire()` 的例外清單：一般同一個模組的兩支腳不能互接（提示訊息寫「這會讓它短路」），但 `tie` 裡的組合可以。TB67S128FTG 的 `tie:[['LO0', 'LO1']]` 讓兩個開汲極錯誤旗標並接，`suggestWiring()` 也是這樣接。
- `refreshNet()` 把結果存進 `NET`。`net(k)` 回傳 k 所在的整個網路，`netInfo(k)` 回傳 `{ m, v33, v5, gnd, gpio, mods, src }`。
- `NET` 只有在 `refreshNet()` 時重建。用 `quiet` 參數改接線時不會觸發 `afterWiring`，要自己呼叫 `refreshNet()`（測試和 `project.js` 的 `loadWires()` 都這樣做）。

### 2.3 電氣模型

`supply(node)` 回傳網路上的電壓：先看模組電源（`netSource()`：開著的馬達電源 V+，或驅動板 VCC 的 5 V），再看開發板有沒有電（`powered()`），最後是 5 V、3.3 V 或 0。

`shorts()` 找出會出事的網路：

```js
export function shorts(){
  const out = [];
  for (const ms of Object.values(NET.groups)){
    const s = new Set(ms), hv = ms.filter(p => /\.V\+$/.test(p) && modOfPin(p)?.type === 'psu' && modOfPin(p).st.on !== false);
    if ((s.has('3V3') || s.has('5V')) && s.has('GND')) out.push({ type:'gnd', ms });
    else if (s.has('3V3') && s.has('5V')) out.push({ type:'rails', ms });
    if (hv.length && (s.has('3V3') || s.has('5V') || ms.some(isGpioName))) out.push({ type:'hv', ms, psu:modOfPin(hv[0]) });
    else if (hv.length && (s.has('GND') || hv.some(p => s.has(p.replace('V+', 'V-'))))) out.push({ type:'psu', ms, psu:modOfPin(hv[0]) });
  }
  return out;
}
```

| `type` | 條件 | 結果 |
| --- | --- | --- |
| `gnd` | 3V3 或 5V 和 GND 在同一個網路 | 開發板斷電 |
| `rails` | 3V3 和 5V 在同一個網路 | 開發板斷電 |
| `hv` | 開著的馬達電源 V+ 碰到 3V3、5V 或 MCU 腳位 | 開發板斷電 |
| `psu` | 馬達電源 V+ 碰到 GND 或它自己的 V− | 只有變壓器關閉輸出（`psuOut()` 回傳 0），開發板不受影響 |

`powered()` 是 `SIM.usb && !shorts().some(x => x.type !== 'psu')`。

`level(node, exclude)` 算出一條線的邏輯電位，回傳 1、0 或浮接的 `null`：

```js
export function level(node, exclude){
  const i = netInfo(node);
  if (i.src) return 1;                                   // 馬達電源或驅動板的 5 V 輸出
  if (!powered()) return null;
  if (i.v33 || i.v5) return 1;
  if (i.gnd) return 0;
  for (const g of i.gpio) if (g !== exclude && SIM.mode[g] === 'out') return SIM.out[g] ? 1 : 0;
  // 模組輸出：任何一個拉低就是低電位（開汲極輸出可以並接，例如驅動板的 LO0 和 LO1）
  let drive = null;
  for (const mp of i.mods){ const v = moduleDrive(mp); if (v === 0) return 0; if (v === 1) drive = 1; }
  return drive;
}
```

- `moduleDrive()` 處理會輸出的模組腳位（按鈕、PIR），並先詢問 `driveHooks`。其他檔案用 `driveHooks.push()` 登記自己的輸出腳，例如 `steppers.js` 登記 TB67S128FTG 的 `LO0`／`LO1`。
- `readPin(p)` 是 SDK 讀 GPIO 時用的：板載按鈕直接看 `SIM.b1`，其他用 `level(p, p)`，浮接時讀到自己的輸出值或 0。
- `moduleState(m)` 依模組種類回傳狀態，例如 LED 是 `{ on: hi('SIG') && gnd('GND') }`，繼電器多一個 `weak`（有電但電壓不夠）。這個物件會交給 `updateModule()` 與元件分頁的 `updateLive()`。
- 類比：`analogVolts()` 算出電壓；`adcRead()` 取第一支有 `adc` 標籤而且接了東西的排針，換成 12 位元並加一點雜訊。TI／NXP 的 ADC 函式再用 `scale(n)` 換成各函式對應的位元數。
- `checkDamage()`：TB67S128FTG 的邏輯腳（`TB67_LOGIC`）碰到超過 5.5 V 會燒毀；溫度感測器的 VCC 超過型號的 `vmax` 會損壞。它回傳新損壞的模組，由 `main.js` 的 `electricalUpdate()` 顯示提示。
- 所有 SDK 的 GPIO 輸出都經過 `pinWrite()`。改變之前呼叫 `pinPreListeners`（步進馬達先把運動積分到這一刻），改變之後寫入 `traceGpio()` 並呼叫 `pinListeners`（SPI 片選、用 GPIO 切換的 STEP、闖關的邊緣計數都掛在這裡）。

### 2.4 接線改變之後：main.js

`afterWiring()` 是接線、更換模組或開發板之後的共同出口：

1. `refreshNet()`。
2. 比較 `hwSig()`（開發板、模組與接線的特徵字串）。邏輯分析儀和它的探棒不算在內，程式碼註解說明分析儀只是量測儀器，接上或移除不需要重新燒錄。特徵改變時呼叫 `hwChanged()`：`UI.rev.hw` 加 1、把 `SIM.flashed.stale` 設為真、停止執行中的程式。
3. `electricalUpdate()`：呼叫 `checkDamage()`；`powered()` 由真變假時停止程式，由假變真時如果韌體還有效就重新開始。
4. 已經檢測過一次時，用 `doCheck(true)` 靜默更新檢測結果。
5. `refreshExample()`：編輯器裡還是上次產生的範例程式時，依新的接線重新產生，讓 `#define` 跟著接線走。
6. `store()` 存到 `localStorage`。

實驗流程用版本號強制：`UI.rev = { hw, code }`，`codeChanged()` 會讓 `code` 加 1。`UI.checkOk`、`UI.built`、`SIM.flashed.rev` 各自存下完成當時的版本號，`renderFlow()` 和 `tryFlash()` 用 `sameRev()` 比較，任何一邊改過就要重做。檢測有錯誤時 `UI.checkOk` 是 `null`，所以錯誤會擋住燒錄，警告不會。

`outputsChanged()` 用 `requestAnimationFrame` 合併多次通知，再由 `applyOutputs()` 更新板載 LED（`boardLedOn()`）、每個模組的 3D（`updateModule()`）、蜂鳴器聲音、繼電器音效、GPIO 狀態列與元件分頁。動畫迴圈 `loop()` 每一格呼叫 `tickSim()`、`canPoll()`（有 CAN 模組時）、`updateSteppers()`，每 6 格再呼叫一次 `applyOutputs()`。

### 2.5 接線檢測：checks.js

`runChecks(src)` 回傳一個陣列，每筆是 `{ sev:'err'|'warn'|'ok'|'info', title, detail, pins, action? }`，依 err、warn、ok、info 排序。順序是：

1. `shorts()` 的每一種短路。
2. GPIO 沒有經過任何模組就直接接到 GND／3V3／5V，以及兩支 GPIO 接在一起。
3. 有用到電源軌時，檢查 + 有沒有接電源、− 有沒有接地。
4. 每個模組：沒有接線的只給 info；`moduleSupport()` 判定不能用的（灰色模組）只給 warn；其餘依 `switch (m.type)` 檢查。TB67S128FTG 的規則多，獨立成 `tb67Checks()`。
5. I2C 位址衝突、接到虛擬序列埠腳、接到板載 LED 腳、USB 沒接。

`analyzeCode(src)` 讓檢測能對照程式：先用 `stripCode()` 去掉註解與字串、展開 `#define`，再用正規表達式找出各家 SDK 的 GPIO 呼叫，得到程式輸出的腳位 `outs`、讀取的腳位 `ins`，以及 `i2c`、`adc`、`spi`、`can`、`step` 是否有用到的旗標。

`main.js` 的 `doCheck()` 把結果畫成清單，錯誤與警告的 `pins` 會在 3D 畫面標成紅色或黃色；有 `action` 的項目會多一個按鈕（例如「更換新的感測器」）。

### 2.6 建議接線與範例程式：codegen.js、sdk.js

`suggestWiring()` 回傳 `[[腳位, 腳位], …]`，規則是：

- 排針 3V3 接 `R.+1`、GND 接 `R.-1`，模組的 VCC／GND 從電源軌取；型號的 `vmin` 大於 3.6 V 時 VCC 改接排針 5V。
- 一般訊號腳避開有 `scl`、`sda`、`vcp`、`led` 標籤的腳與板載按鈕腳，類比模組用有 `adc` 標籤的腳。
- I2C、SPI 的元件與分析儀探棒用 `tail` 記住每條線目前的尾端，一個接一個串下去（排針每孔一條線，模組腳位最多兩條）。
- 驅動板：馬達電源 V+／V− 接 VIN／PGND，GND 與 IOREF 從電源軌取，CLK 接 `board.step` 的計時器輸出，`LO0` 與 `LO1` 並接。
- `moduleSupport()` 判定不能用的模組完全不接。

`exampleCode()` 依目前的開發板產生完整的 `main.c`。腳位由 `signalMcu()` 決定：模組腳位已經接到 MCU 就用實際的腳，否則用建議接線的腳。各家 SDK 的寫法由 `sdkFor(b)` 回傳的物件提供：

| 欄位 | 用途 |
| --- | --- |
| `name`、`print`、`float` | SDK 名稱、輸出函式名稱（`printf`、`UARTprintf`、`PRINTF`）、範例要不要用 `%f` 印小數 |
| `includes`、`globals`、`init` | 標頭檔、全域變數、`main()` 開頭的初始化 |
| `def`、`cfgOut`、`cfgIn` | 一支腳位的 `#define` 與輸出／輸入設定 |
| `set`、`pin`、`tog`、`read` | 依條件輸出、輸出固定值、切換、讀取 |
| `delay` | 延遲幾毫秒的寫法 |
| `i2c`、`adc`、`spi`、`step`、`can` | 匯流排、ADC、計時器 PWM、CAN 的程式片段 |

`can` 只有在晶片有 CAN 時才會用到，MSP430 的物件沒有這個欄位。I2C 感測器的驅動程式（`driver()`）只透過 `I2C_Write`／`I2C_Read`，SPI 元件（`spiDriver()`）只透過 `SPI_Xfer` 與 CS 腳，所以各家 SDK 共用同一份。產生的主迴圈每 10 ms 跑一次：每 50 次切換 LED，每 100 次回報一次，每 200 次執行 `slow` 裡的程式（繼電器切換）。

### 2.7 編譯：compiler.js

`compile(src)` 回傳 `{ ok, diag, js, size }`。`diag` 的每一筆是 `{ sev:'error'|'warning', line, col, msg }`，`ui/build.js` 把它印成 `main.c:行:欄: error: …` 的 gcc 格式。檢查依序是：括號配對、缺少分號、未宣告的函式與識別字、沒有 `main`，以及有 `while (1)` 但整個程式都沒有延遲函式（警告）。

呼叫到的函式依下面的順序判斷：

- 使用者定義的函式、`#define` 巨集、`BUILTIN_FNS`（`makeAPI()` 回傳物件裡的函式）：正常。
- 只有原型、沒有定義：連結錯誤，訊息是 `undefined reference to` 加上函式名稱與「只有宣告，沒有定義」。
- 名稱符合 `VENDOR_PREFIX`（`DL_`、`GPIO_`、`FLEXCAN_` 等 TI／NXP 前綴）：警告「是 SDK 的設定函式，模擬器沒有實作，執行時會略過」。
- 其他：錯誤 `implicit declaration of function`。`HAL_` 不在 `VENDOR_PREFIX` 裡，所以沒有實作的 STM32 HAL 函式是錯誤，不是警告。

沒有錯誤時用 `transpile()` 把 C 轉成 async JavaScript，並且先用 `new AsyncFunction(...API_NAMES, js)` 試建一次，抓出轉換後的語法錯誤。`size` 是依原始碼長度估算的數字，只用來顯示。下面是一段 C 和它實際轉出來的結果：

```text
#define LED_Pin GPIO_PIN_5
uint8_t buf[4] = {1, 2, 3, 4};
static int add(int a, int b) { return a + b; }

int main(void)
{
  int16_t z = (int16_t)(40000);
  while (1) {
    HAL_GPIO_TogglePin(GPIOA, LED_Pin);
    printf("%d\r\n", add(z, 1));
    HAL_Delay(10);
  }
}
```

```js
with (__env) {
const LED_Pin = GPIO_PIN_5;
let buf = __arr(4, [1, 2, 3, 4]);
async function add(a, b) { return a + b; }

async function main()
{
  let z = __i16(40000);
  while (1) { await __y();
    HAL_GPIO_TogglePin(GPIOA, LED_Pin);
    printf("%d\r\n", await add(z, 1));
    await HAL_Delay(10);
  }
}
;return await main();
}
```

轉換規則：

- `#include` 刪除；`#define` 變成 `const`，帶參數的變成箭頭函式。
- 函式原型刪除，函式定義變成 `async function`；呼叫使用者函式（`main` 以外）與 `ASYNC_BUILTIN` 裡的函式時前面加 `await`。
- 陣列變成 `__arr(長度, 初值)`；`TYPES` 裡的純量型別變成 `let`；`xxx_t` 這類結構與 SDK 型別沒有初值時變成 `__obj()`（讀取沒設定過的欄位得到 0，名稱含 data／buf 的欄位自動是陣列）。
- 整數轉型變成 `__u8`、`__i16` 這類截斷函式，其他轉型直接刪除。宣告的型別本身不會截斷：`uint8_t x = 300;` 在執行時就是 300，`7 / 2` 是 3.5。
- 數字後綴（`u`、`L`、`f`）刪除，函式參數與 `=` 右邊的取址 `&` 刪除，`->` 換成 `.`。
- `insertYields()` 在每個 `while`、`for`、`do` 迴圈開頭插入 `await __y();`。
- 程式碼註解說明不用 lookbehind 的原因：iOS 16.3 以前的 Safari 不支援。

### 2.8 執行：runtime.js、hal.js、hal-vendor.js

`startProgram()` 的核心幾行：

```js
  const r = { stop:false, t0:performance.now(), id:++runSeq }; RUN = r;
  SIM.out = {}; SIM.mode = {}; resetBuses(); hooks.outputs();
  hooks.run('run'); hooks.sys(`MCU 重設，從 ${hexAddr(flashBase(bench.board))} 開始執行`);
  let fn; try { fn = new AsyncFunction(...API_NAMES, SIM.flashed.js); } catch (e){ hooks.run('fault'); hooks.sys('無法啟動：' + e.message, 'er'); return; }
  const api = makeAPI(r);
  fn(...API_NAMES.map(k => api[k])).then(() => {
```

`makeAPI(r)` 回傳的物件裡，每一個鍵都變成這個 async 函式的同名參數，所以 C 程式裡的 `HAL_GPIO_WritePin(...)` 直接呼叫到 `api.HAL_GPIO_WritePin`。`API_NAMES` 就是 `Object.keys(makeAPI(...))`，編譯器也用它判斷哪些名稱存在，所以 `hal.js` 開頭的註解說：新增函式時加在 `makeAPI` 裡，編譯器會自動認得。

沒有實作的名稱透過 `with (__env)` 查找：

```js
  const known = new Set(Object.keys(api));
  const stub = () => 0;
  api.__env = new Proxy({}, {
    has:(t, k) => typeof k === 'string' && !known.has(k) && (VENDOR_PREFIX.test(k) || /^[A-Z][A-Z0-9_]*$/.test(k) || /^k[A-Z]\w*$/.test(k)),
    get:(t, k) => typeof k === 'string' && VENDOR_PREFIX.test(k) && !/^[A-Z][A-Z0-9_]*$/.test(k) ? stub : 0,
    set:() => true,
  });
```

符合 `VENDOR_PREFIX` 的函式變成回傳 0 的空函式，全大寫或 `k` 開頭的常數變成 0。

- 停止：API 函式大多先呼叫 `chk()`，`r.stop` 為真時丟出 `STOP`。`stopProgram()` 只要把 `RUN.stop` 設為真，程式在下一次呼叫 API 時就會結束；`startProgram()` 的 `catch` 看到 `STOP` 不做任何事。
- 讓出執行權：`__y()` 每呼叫 2000 次就 `await sleep(0)` 一次，所以沒有延遲的迴圈也會定期讓出執行權。
- 延遲：`waitMs()` 從「上一次延遲應該結束的時間」起算（落後 50 ms 以內），程式碼註解說明這樣平均週期才會和真的 MCU 一樣，韌體用固定 dt 算的位置與加減速才會和送出的脈波一致。
- 結束：`main()` 返回時狀態變成 `done`；其他例外變成 `fault` 並印出 `HardFault：…`，`ReferenceError` 會改寫成「使用了未宣告的變數」。

ST 的 HAL 函式直接寫在 `makeAPI()` 的 `api` 物件裡，例如 `HAL_GPIO_WritePin(port, mask, st){ chk(); for (const p of pinsOf(port, mask)) pinWrite(p, st); hooks.outputs(); }`。TI 與 NXP 的函式在 `hal-vendor.js` 的 `vendorAPI(ctx)`，由 `makeAPI()` 傳入 `{ chk, sleep, waitMs, outputs, print }` 後用 `Object.assign` 合併。各家 SDK 的參數最後都換成 MCU 腳位名稱再呼叫 `pinWrite()`／`pinToggle()`／`readPin()`，例如 `DL_GPIO_setPins(GPIOA, DL_GPIO_PIN_0)` 換成 `PA0`、MSP430 的 `GPIO_PORT_P1` 加 `GPIO_PIN0` 換成 `P1.0`、C2000 的 `GPIO_writePin(31, …)` 換成 `GPIO31`。NXP 依傳入的 GPIO 物件與 `board.pinStyle` 換算（`PTB22`、`PIO1_4`、`GPIO1_IO09`、`P0_10`）。範例程式會呼叫、但模擬器不需要做事的初始化函式列在 `NOOPS`。

### 2.9 匯流排與元件模型：buses.js、devices.js、spidev.js

`hal.js` 與 `hal-vendor.js` 的匯流排函式都經過 `buses.js`，邏輯分析儀才看得到每一筆傳輸。

- UART：`uartOut(s)` 在 `TRACE.on` 時用 `traceUART()` 記錄波形，再呼叫 `hooks.serial`。
- I2C：`i2cWrite()`、`i2cRead()`、`i2cMemRead()`、`i2cMemWrite()`、`i2cProbe()` 用 `sim.js` 的 `i2cFind()` 找元件。`i2cDevices()` 只列出有供電、有接地，而且 SCL／SDA 接在本板 I2C 腳上的感測器；位址重複時回傳 `'conflict'`，等於沒有元件回應（NACK）。元件模型由 `devices.js` 的 `makeDevice(v, readT, readRH)` 建立，介面是 `{ addr, read(reg, n), write(reg, bytes), tx(bytes), rx(n) }`，失敗時回傳 `null` 或 `false`。
- SPI：`spiDevices()` 列出供電正確、SCK／MISO／MOSI 接對的從機。CS 腳的變化由 `pinListeners` 通知元件的 `select()`／`deselect()`，`spiTransfer(tx)` 對每個位元組呼叫被選中元件的 `xfer(b)`，多個從機同時被選中時把 MISO 做 AND。元件模型在 `spidev.js` 的 `makeSpiDevice(v, st, readT, readCJ)`，Flash 的內容存在 `m.st.mem`，註解寫明斷電不會消失。
- CAN：狀態在 `CAN` 物件。`canLink()` 判斷收發器的供電與 TXD／RXD 接線；`canSend()` 在連線正常而且測試節點開著時才算有 ACK；`canPoll()` 讓測試節點每 500 ms 送出 ID 0x200；`canPending()`、`canRecv()` 給 SDK 的接收函式用。
- `resetBuses()` 在每次程式開始時清除 CAN 控制器、PWM 與 SPI 選取狀態。

### 2.10 訊號紀錄與邏輯分析儀：trace.js、protocols.js、analyzer.js

```js
export const TRACE = { on:false, cursor:0, lines:new Map(), keep:12e6, n:0 };
const nowUs = () => performance.now() * 1000;
/** 目前的訊號時間：實際時間，或上一段傳輸結束的時間（傳輸需要時間，後面的事件不能和它重疊） */
export const tNow = () => Math.max(nowUs(), TRACE.cursor);
```

- 只有工作台上有分析儀時才記錄：`sim.js` 的 `syncTrace()` 在新增或移除模組時呼叫 `setTrace()`。
- 每條線以來源為鍵：MCU 腳位名稱，CAN 匯流排用 `'CAN.BUS'`。格式是 `{ init, t:[微秒…], v:[0 或 1…] }`。
- `traceI2C()`、`traceUART()`、`traceSPI()`、`traceCAN()` 依固定速率合成位元層級的波形，先用 `reserve()` 預留傳輸時間、推進 `TRACE.cursor`，所以前後兩筆傳輸不會重疊。比 20 ns 短的脈衝會被 `edge()` 合併，超過 `keep`（12 秒）的紀錄會被刪掉。
- `protocols.js` 是純函式：`sampleSig()` 依取樣率量化邊緣，`decodeI2C()`、`decodeUART()`、`decodeSPI()`、`decodeCAN()` 回傳 `{ anns, stats }`，`canFrameBits()` 與 `crc15()` 產生 CAN 訊框的位元、填充位元與 CRC。
- `analyzer.js`：`probeSource()` 判斷探棒接到什麼（`open`、`const`、`line`、`float`），`expectedSource()` 與 `probeOk()` 判斷接得對不對，`capture(m, t0, t1)` 取出每個通道的訊號（沒有共地時疊加雜訊），`analyze(cap, opt)` 取樣、解碼並用 `diagnose()` 找出可能的原因，回傳 `{ chans, anns, stats, issues }`。
- 視窗在 `ui/analyzer.js`：`startCapture()` 錄完一段後如果探棒上沒有任何變化，會像觸發一樣繼續等，最多 10 秒；`reanalyze()` 解碼後呼叫 `hooks.analyzed`。點選波形的說明與分步教學來自 `lessons.js` 的 `explain()` 與 `LESSONS`。

### 2.11 步進馬達：steppers.js

- 兩組 STEP 輸出存在 `PWM`。各家 SDK 的計時器函式用 `stepIndex(inst, ch)` 或 `stepIndexes(inst)` 找出是 `board.step` 的第幾組，再呼叫 `pwmSet(k, 頻率)` 與 `pwmRun(k, 開關)`。比對的依據是 `board.step[k].inst` 等於 SDK 控制代碼物件的 `name`（例如 `htim3` 是 `{ name:'TIM3' }`）。
- `stepperTick()` 先對每塊驅動板跑 `driverTick()`（錯誤偵測與解除、晶片溫度、上電時電氣角回到 45°），再對每顆馬達跑 `advance()`，每 0.2 ms 積分一次轉子。
- `driverInputs()` 從實際接線讀出供電、ENABLE、方向、STEP 頻率、微步與電流，`coilMap()` 判斷馬達線圈接到哪一相、有沒有接錯。
- `pinPreListeners` 讓 DIR、EN、CLK 改變之前先積分到那一刻；`pinListeners` 處理用一般 GPIO 切換 CLK 的情況，每個上升緣前進一個微步。
- `main.js` 的 `updateSteppers()` 每一格呼叫 `stepperTick()`，再用 `motorInfo()` 與 `motorOf()` 的結果呼叫 `updateModule(m, { deg, stalled, en, load, bits }, t)`。

### 2.12 輸出到畫面

- `scene.js` 的 `buildBench()` 清掉舊的物件，重建開發板、電源軌、每個模組（`buildModule(m, slotPos(m), 群組)`）與所有杜邦線。它在 `hooks.benchChanged` 對應的 `onBenchChanged()` 與 `benchLoaded()` 裡被呼叫；只改接線時則由 `buildWireMesh()`／`disposeWireMesh()` 單獨處理一條線。
- `modules3d.js` 的 `buildModule()` 先畫所有模組共用的部分（電路板、絲印、腳位、`addPin()` 建立可點選的腳位），再用 `switch (m.type)` 加上各自的零件，需要更新的物件存在 `G.mods[m.id]`。`updateModule(m, s, t)` 依 `s` 改變外觀，例如：

```js
const lit = (V, on, color) => { if (V.mat){ V.mat.emissive.setHex(on ? color : 0); V.mat.emissiveIntensity = on ? 1.6 : 0; } if (V.glow){ V.glow.visible = on; if (on) V.glow.material.color.setHex(color); } };
```

- 灰色模組（`moduleSupport()` 不通過）在建立時用 `greyOut()` 變灰並加上 `offTag()` 標籤，`updateModule()` 只把發光效果關掉就返回。
- 面板方面：元件分頁的 `updateLive()` 顯示模組目前的狀態，序列埠由 `serialOut()` 處理，GPIO 狀態列在 `applyOutputs()` 裡更新。`main.js` 呼叫 3D 之前會先檢查 `G.ready`；WebGL 無法啟用時畫面會顯示提示，面板仍可接線、檢測、編譯與燒錄。

## 3. 主要資料結構

### 3.1 開發板

所有開發板都整理成同一種物件，放在 `BOARDS` 與 `BOARD_BY_ID`（`boards.js`）。ST 的板子是 `RAW` 裡的一列：

```js
// [id, 名稱, 系列, MCU, 核心, MHz, Flash KB, RAM KB, 板型, 燒錄器, Device ID, 封裝, LED, 按鈕, VCP, 其他]
const RAW = [
  ['nucleo-h743zi2', 'NUCLEO-H743ZI2', 'H7', 'STM32H743ZIT6', 'Cortex-M7', 480, 2048, 1024, 'n144', 'ST-LINK V3E', '0x450', 'LQFP144', H7_LEDS, B1, V144, { page:'nucleo-h743zi' }],
```

`buildBoard()` 依板型（`n144`、`n64`、`n32`、`pill`、`disco`）決定排針（`HEADERS`）、Arduino 腳位對照、I2C、SPI、CAN 腳與 STEP 計時器；沒有 CAN 的 MCU 列在 `NOCAN`，需要不同 STEP 計時器的 MCU 列在 `STEP_FIX`。

TI 與 NXP 用 `board-kit.js` 的 `makeBoard(o)`，各系列再包一層範本函式。例如 TM4C123：


排針的每一支腳是 `makeBoard()` 或 `buildBoard()` 產生的物件：


`kind` 是 `'gpio'`、`'pwr'` 或 `'gnd'`；`mcu` 是 MCU 腳位名稱（Arduino 標籤時由 `pins` 對照表換算）；`tags` 標出這支腳的功能：

| 標籤 | 意義 |
| --- | --- |
| `adc` | 有 ADC 功能 |
| `scl`、`sda` | 本板設定的 I2C 腳 |
| `vcp` | 虛擬序列埠 TX／RX |
| `led` | 板上也接著板載 LED |
| `btn` | 板載按鈕（只有 `makeBoard()` 會加） |
| `pwm` | Nucleo 的 Arduino PWM 腳（只有 ST 的 `buildBoard()` 會加） |
| `sck`、`miso`、`mosi`、`cs` | 本板設定的 SPI 腳 |
| `cantx`、`canrx` | 本板設定的 CAN 腳 |
| `step` | STEP 用的計時器輸出 |

模擬時常用的欄位：`i2c.inst` 與 `spi.inst` 要等於 SDK 控制代碼物件的 `name`（`hal-vendor.js` 的 `onBus()`、`spiOk()` 與 `hal.js` 的 `spiOk()` 就是這樣比對）；`step` 的每一組是 `{ pin, tim, inst, ch?, drv?, out?, pcfg? }`；`vcp` 是 `{ periph, tx, rx, handle }`；`sdk` 是 `stm32hal`、`mspm0`、`msp430`、`tivaware`、`c2000`、`mcux` 之一；`pinStyle` 決定 NXP 腳位名稱的格式；`form` 必須是 `FORMS` 的鍵，3D 依它決定板子大小。

晶片沒有某種周邊時，`spi`、`can`、`step` 是 `null`，對應的 `noSpi`、`noCan`、`noStep` 可以放一句原因，例如 `noStep:'模擬器還沒有設定 MSP430FR6989 的計時器輸出腳位。'`。`support.js` 的 `FEATURES` 用這句話當作原因，沒有填時用預設句子；`NEEDS` 決定哪些模組需要哪種周邊：

```js
const NEEDS = { tc:'spi', flash:'spi', la_spi:'spi', can:'can', la_can:'can', stepper:'step' };
```

`moduleSupport(type, b)` 回傳 `{ ok:true }`、`{ ok:true, note }`，或 `{ ok:false, feat, lack, why, tip, alt }`，`alt` 是 `altBoards()` 找出的替代開發板。TB67S128FTG 驅動板不在 `NEEDS` 裡：沒有 STEP 輸出的板子仍然可以用，CLK 改接一般 GPIO。

### 3.2 模組種類：MODULE_TYPES（parts.js）

```js
  led: {
    name:'LED 模組', short:'LED', w:20, d:14, pcb:0x1c3a57,
    pins:[['SIG', '訊號：高電位點亮（內含限流電阻）'], ['GND', '接地']],
```

```js
MODULE_TYPES.tb67 = {
  name:'TB67S128FTG 步進馬達驅動板', short:'TB67', w:24, d:58, big:true, pitch:4.4, pitchR:5, pcb:0x1f6f43, driver:true, bridge:[['GND', 'PGND']], tie:[['LO0', 'LO1']],
  pins:TB67_PINS,
```

| 欄位 | 用途 |
| --- | --- |
| `name`、`short` | 完整名稱；`short` 用在 `moduleLabel()`，同種模組有多個時加上編號 |
| `w`、`d`、`pcb`、`pitch`、`pitchR` | 3D 電路板的寬、深、顏色，左右兩欄腳位的間距 |
| `pins` | `[名稱, 說明, 'R'?]`；第三欄是 `'R'` 的腳畫在模組右側（`pinLayout()`），例如 TB67S128FTG 的 VIN、PGND、VCC 與馬達線 |
| `variants` | 可更換的型號，`variantOf(type, id)` 找不到時回傳第一個 |
| `big` | 佔兩格（`slot` 加 `slot2`） |
| `bridge` | 板上本來就相通的腳，`netMap()` 會合併 |
| `tie` | 允許同一個模組互接的腳位組合，`addWire()` 的例外 |
| `analyzer` | 邏輯分析儀的協定（`i2c`、`uart`、`spi`、`can`），由 `LA()` 產生 |

型號的共同欄位是 `id`、`name`、`part`、`grade`（1 入門、2 進階、3 高階）、`better`（比上一級好在哪裡）、`specs`（`[名稱, 值]`）、`links`。其他欄位依種類而定，例如 `vmin`／`vmax`（電壓範圍）、`addr` 與 `dev`（I2C 位址與 `makeDevice()` 用的模型）、`v`（馬達電源電壓）、`rate`（分析儀最高取樣率）、`step`／`T`／`J`／`rated`（馬達參數）、`heat`（驅動板的發熱係數）。`bus`、`motor`、`psu`、`driver` 這幾個旗標目前沒有程式讀取，模組的行為都是依 `type` 字串判斷。

清單順序：`MODULE_GROUPS` 決定元件分頁「新增模組」的分組與按鈕，`TYPE_ORDER` 只在測試裡用到，`DEFAULT_MODULES` 是預設工作台。

### 3.3 杜邦線

```js
  const w = { id:++wireSeq, a, b, color:color || autoColor(a, b), bend:(Math.random() * 2 - 1) * 3.2 };
```

`a`、`b` 是腳位 id，`color` 是 `WIRE_COLORS`（`scene/util.js`）的鍵，沒有指定時由 `autoColor()` 依用途決定（電源紅、地黑、SCL 黃、SDA 藍、馬達線依常見顏色）。`bend` 讓每條線的弧度不同。`scene.js` 的 `buildWireMesh()` 會在物件上掛 `mesh`。存檔時只存 `[a, b, color]`。

### 3.4 作品存檔與分享網址：project.js

本機存檔、分享網址與闖關都用同一種格式：

```js
export function snapshot({ code, example } = {}){
  return {
    v:1, board:bench.board.id,
    modules:bench.modules.map(m => ({ id:m.id, type:m.type, variant:m.variant, slot:m.slot,
      ...(m.type === 'pot' ? { pot:Math.round(m.st.pot * 100) / 100 } : {}),
      ...(isStepper(m) ? { div:motorOf(m).jdiv, load:motorOf(m).load } : {}),
      ...(isDriver(m) ? { jdiv:drvOf(m).jdiv, vref:drvOf(m).vref } : {}),
      ...(m.type === 'psu' && m.st.on === false ? { on:false } : {}) })),
    wires:wires.map(w => [w.a, w.b, w.color]),
    ...(example ? { example:true } : typeof code === 'string' ? { code } : {}),
  };
}
```

`loadBench(s)` 重建開發板與模組（沿用存檔裡的模組 id 與格子），`loadWires(s)` 再接上所有線並 `refreshNet()`。程式碼由介面處理：`example:true` 表示程式是範例程式，載入時用 `exampleCode()` 重新產生，所以分享網址不必帶程式碼。

```js
export async function encodeShare(state){
  const raw = new TextEncoder().encode(JSON.stringify(state));
  if (typeof CompressionStream === 'function'){ try { return 'z' + b64url(await pipe(raw, CompressionStream)); } catch (_){ /* 用未壓縮格式 */ } }
  return 'j' + b64url(raw);
}
```

分享網址是 `#p=` 加上這個字串：`z` 開頭是 `deflate-raw` 壓縮後的 base64url，沒有 `CompressionStream` 的舊瀏覽器用 `j` 開頭的未壓縮 JSON。`decodeShare()` 依第一個字元解開，`v` 不是 1 或沒有 `board` 時丟出錯誤。`main.js` 啟動時用 `/^#p=([\w-]+)$/` 讀取網址，讀完用 `history.replaceState()` 把 `#p=` 拿掉。

## 4. 怎麼擴充

每一種擴充做完都跑一次 `npm run check`。很多測試會走過全部 `BOARDS`、全部 SDK 與全部關卡，新加的東西會自動被涵蓋。

### 4.1 新增開發板

ST（`boards.js`）：

1. 在 `RAW` 加一列，欄位順序見上面的註解。最後一欄可以放 `pins`（覆寫 Arduino 腳位對照，例如 `{ pins:{ D7:'PC14', D8:'PC15' } }`）、`page`（開發板產品頁網址裡的名稱，沒填時用 `id`）、`board`（開發板資料的網址，用來取代 ST 的產品頁）、`xtal`、`pcb`。
2. MCU 沒有 CAN 控制器時，把型號開頭加進 `buildBoard()` 的 `NOCAN`；這顆 MCU 要用和板型預設不同的 STEP 計時器時，加進 `STEP_FIX`。CAN 的種類依系列判斷（H7、H5、G4、U5 是 FDCAN，F0、F1、F3 是單一 bxCAN）。
3. 新的系列要加進 `VENDORS` 的 `series`。元件分頁的晶片清單是依 `VENDORS` 分組，系列不在裡面的板子不會出現。

TI（`boards-ti.js`）與 NXP（`boards-nxp.js`）：

1. 同系列的晶片直接用現成的範本函式加進 `TI_BOARDS` 或 `NXP_BOARDS`：TI 有 `m0g`、`m0l`、`fr2355`、`msp`、`tm123`、`tm129`、`c79`、`c49`，NXP 有 `kk`、`kl`、`l55`、`l8`、`rt`、`mcx`。
2. 新的系列用 `base(o, sdk, tool)`（TI）或 `nxp(o, board)`（NXP）寫一個新的範本，它們最後都呼叫 `makeBoard(o)`。除了 `mcu`、`series`、`core`、`mhz`、`flash`、`ram`、`pkg`、`prog`、`dbg` 這些基本資料，要填的欄位有：`header`（排針標籤，`hdr()` 會在前後補電源腳並補成偶數）、`pins`（有 Arduino 標籤時）、`adc`、`i2c`、`leds`、`btn`、`vcp`、`spi` 或 `noSpi`、`can` 或 `noCan`、`step` 或 `noStep`、`adcDrv`、`adcInst`、`pinStyle`。排針數量是奇數時 `makeBoard()` 會丟出錯誤。
3. 腳位名稱的格式要和 `hal-vendor.js` 換算出來的一樣（見 2.8），`i2c.inst`、`spi.inst`、`step[].inst` 要等於 SDK 控制代碼物件的 `name`，否則程式跑起來找不到元件或計時器。
4. 用到新的 ADC 驅動（`adcDrv`）、SPI 驅動（`spi.drv`）或計時器（`step[].drv`）時，`sdk.js` 要能產生它的程式片段，`hal-vendor.js` 要能模擬。

測試會檢查每塊板子：排針至少 20 支、I2C 腳在排針上、有 ADC 腳、MCU 腳位不重複；預設模組的建議接線加範例程式要能編譯而且沒有任何診斷訊息，檢測沒有錯誤或警告；有 SPI、CAN、STEP 的板子還要通過對應的測試。

### 4.2 新增模組種類

1. `parts.js`：在 `MODULE_TYPES` 加一筆（`name`、`short`、`w`、`d`、`pcb`、`pins`、`variants`，需要時加 `big`、`bridge`、`tie`），並把它放進 `MODULE_GROUPS`，元件分頁才會出現新增按鈕。
2. `sim.js`：在 `moduleState()` 加一個 `case`，用 `level()`、`supply()`、`hasGnd()` 算出狀態。模組會輸出訊號時，在 `moduleDrive()` 處理，或從自己的檔案用 `driveHooks.push()` 登記。
3. `modules3d.js`：在 `buildModule()` 的 `switch (m.type)` 加上外觀，需要更新的物件放進 `V`；在 `updateModule()` 依狀態更新。沒有加 `case` 時，模組仍會畫出共用的電路板與腳位。
4. `main.js`：一般模組由 `applyOutputs()` 自動呼叫 `moduleState()` 與 `updateModule()`。狀態不是來自 `moduleState()` 的（像驅動板、馬達電源、分析儀、CAN），要在 `applyOutputs()` 裡另外處理。
5. `checks.js`：在 `runChecks()` 的 `switch (m.type)` 加規則，見 4.4。
6. `codegen.js`：只有一般 GPIO 訊號腳的模組加進 `SIGNAL`，`suggestWiring()` 就會自動接訊號腳，電源由 `power()` 處理；其他接法要在 `suggestWiring()` 裡寫。範例程式在 `exampleCode()` 的 `for (const m of mods)` 迴圈裡用 `define()` 定義腳位，再把程式碼推進 `blink`、`loop`、`report`、`slow` 或 `drivers`，寫法一律透過 `sdk` 物件，這樣六種 SDK 都能產生。
7. `support.js`：需要 SPI、CAN 或 STEP 時加進 `NEEDS`（沒有這種周邊的板子上會變灰色）。SPI 元件還要加進 `buses.js` 的 `SPI_TYPES` 與 `SPI_PINS`，在 `spidev.js` 的 `makeSpiDevice()` 加模型，在 `codegen.js` 的 `spiDriver()` 加讀取範例。I2C 感測器的新型號則是在 `devices.js` 的 `makeDevice()` 與 `codegen.js` 的 `driver()` 加。
8. `ui/inspector.js`：可以互動的控制項加在 `controls(m, v)`，即時狀態文字加在 `updateLive()`，事件在 `initInspector()` 裡處理，再呼叫 `main.js` 傳進來的 `ACTIONS`。
9. 測試：用 `setup('nucleo-f401re', [{ type:'新種類' }])` 確認建議接線加範例程式能編譯、`runChecks()` 沒有錯誤或警告；需要時用 `run()` 驗證執行結果。

### 4.3 新增 SDK 函式

1. 模擬：STM32 HAL 加在 `hal.js` 的 `makeAPI()` 的 `api` 物件；TI 與 NXP 加在 `hal-vendor.js` 的 `vendorAPI()` 裡對應 SDK 的 `Object.assign` 區塊。函式開頭先呼叫 `chk()`，程式才停得下來。GPIO 用 `write`、`toggle`、`read`（最後是 `pinWrite()`、`pinToggle()`、`readPin()`），改完輸出後呼叫 `outputs()`；匯流排呼叫 `buses.js` 的函式；計時器呼叫 `pwmSet()`、`pwmRun()`。
2. 會等待的函式（回傳 Promise）要把名稱加進 `compiler.js` 的 `ASYNC_BUILTIN`，否則轉譯後不會加 `await`。
3. 常數直接加成 `api` 的屬性。沒有加的全大寫常數會被 `__env` 當成 0，不會報錯，所以常數值錯了不容易發現。
4. 只需要「不做事」的初始化或設定函式，TI 與 NXP 加進 `hal-vendor.js` 的 `NOOPS`；ST 直接在 `makeAPI()` 寫成 `noop`。
5. 範例程式要用這個函式時，改 `sdk.js` 裡對應 SDK 物件的欄位（例如 `delay`、`adc`、`step`、`can`）。測試要求每塊板子的範例程式編譯後完全沒有診斷訊息，所以範例用到的函式都必須在 `api` 或 `NOOPS` 裡，不能只靠 `VENDOR_PREFIX` 略過。
6. 新函式是 GPIO 輸出或讀取時，要更新 `checks.js` 的 `analyzeCode()`；是匯流排或計時器函式時，更新它回傳的 `i2c`、`adc`、`spi`、`can`、`step` 正規表達式。否則檢測會誤報「程式沒有控制 …」或「程式沒有使用 SPI」。

`API_NAMES` 與 `BUILTIN_FNS` 都是從 `makeAPI()` 算出來的，編譯器不需要另外登記。

### 4.4 新增接線檢測規則

`runChecks()` 裡有幾個區域函式可以直接用：

```js
      case 'led': gpio('SIG', 'out'); gnd(); break;
      case 'rgb': gpio('R', 'out'); gpio('G', 'out'); gpio('B', 'out'); gnd(); break;
```

- `gnd(n)`：這支腳有沒有接地。`vcc(min, max, why)`：VCC 的電壓在不在範圍內。`gpio(n, dir)`：`dir` 是 `'out'`、`'in'` 或 `'adc'`，會檢查有沒有接到 MCU、是不是 ADC 腳，並對照 `analyzeCode()` 的結果；接對時回傳 MCU 腳位名稱。
- 自己寫規則時用 `add(sev, title, detail, pins, action)`。`pins` 是要在 3D 畫面標出的腳位 id，常用 `netPins(node)`（這個網路上所有接了線的腳位）或 `pinsOr(id)`（沒接線時就標它自己）。`action` 是 `{ label, fn }`，會在檢測結果裡變成一個按鈕。
- 和單一模組有關的規則放進 `switch (m.type)`；跨模組的規則（例如 I2C 位址衝突）放在模組迴圈之後。
- `err` 會擋住燒錄，`warn` 不會。不確定使用者是不是故意這樣接時，用 `warn` 或 `info`。
- 測試要求所有板子的建議接線加範例程式都沒有 `err` 或 `warn`，新規則不能誤判正確的接法。再仿照「接錯的狀況」那個測試，故意接錯並檢查新的標題有出現。

### 4.5 新增闖關或故障挑戰（missions.js）

闖關課程是 `MISSIONS` 的一筆：`id`、`no`、`title`、`short`、`mods`（這一關的模組）、`intro`、`steps`（每一步 `{ t, ok:c => … }`）、`hints`、`learn`，需要時加 `edge(c, pin, v)`（每次 GPIO 改變時呼叫，用來數閃爍次數）或 `watch(c)`（每次判定前呼叫）。故障挑戰是 `CHALLENGES` 的一筆，例如：

```js
  { id:'c1', no:1, title:'LED 不會亮', mods:[{ type:'led', variant:'led-red' }],
    symptom:'程式在跑，板載 LED 也在閃，可是外接的 LED 一直不亮。',
    bug:(api, c) => api.unwire(api.wireAt(P(c.m('led'), 'GND'))),
    fixed:c => (c.cnt.blink || 0) >= 3, edge:blinkEdge('led'),
    hints:['LED 要亮，電流要有完整的迴路：從 GPIO 出來，經過 LED，回到哪裡？', '看看 LED 模組的每一支腳都有接線嗎？'],
    learn:'LED 的 GND 沒接：電流沒有回路，GPIO 輸出高電位也不會有電流。所有模組都要和開發板共地。' },
```

- 製造問題用 `bug(wireApi, c)` 改接線（`wireAt`、`unwire`、`wire`、`header`、`rail`、`freeGpio`），或用 `code(src)` 改程式。需要特定周邊時填 `needs`（`'spi'`、`'can'`、`'step'`），`boardFits()` 會在目前的板子不符合時換成預設開發板。
- `prepare(x, boardId)` 擺好工作台：闖關只放模組、線讓使用者自己接；故障挑戰先照建議接線接好、產生範例程式，再套用 `bug` 或 `code`。它也算出 `exp`（模組腳位對應到程式預期的 MCU 腳），判定時用 `c.exp(m, n)` 取得。
- 判定用的 `c` 由 `makeCtx()` 建立：`c.b`、`c.scl`、`c.sda`、`c.m(type)`、`c.exp()`、`c.label()`、`c.running`、`c.serial`、`c.reflashed`、`c.cnt`、`c.v`、`c.flag`。`J`（`gpio`、`on`、`gnd`、`v33`、`v5`）與 `nums()` 是常用的小工具。`ui/learn.js` 每 0.2 秒呼叫一次 `evaluate()`。
- `c.flag` 的值由介面設定，例如 `learnAnalyzed()` 設定 `uartOk`、`uartBad`。需要新的介面事件時，要在 `ui/learn.js` 加對應的程式。
- `index.html` 學習地圖的分頁標籤把關卡數寫死成「闖關課程（6）」與「故障挑戰（10）」，README 也寫了關卡清單，新增關卡時要一起改。
- 測試會用六種 SDK 準備每一關，確認解答的接線通過檢測、程式能編譯，故障挑戰一開始真的有問題。想確認新的一關真的能過關，把它加進「闖關判定」測試的清單。

## 5. 測試與除錯

測試全部在 `tests/core.test.js`，用 Node 內建的 `node:test` 與 `node:assert/strict`，只 import `src/core/`，不需要瀏覽器。工作台由 `setup` 準備：

```js
function setup(boardId, mods = DEFAULT_MODULES){
  resetBench(); setBoard(boardId, true);
  mods.forEach(m => addModule(m.type, m.variant, true));
  suggestWiring().forEach(([a, b]) => assert.ok(addWire(a, b, null, true), `接線失敗 ${a} → ${b}`));
  refreshNet();
}
```

其他輔助函式：`problems(res)` 只留下 `err` 與 `warn` 的標題；`until(cond, ms)` 輪詢等到條件成立（註解說明用輪詢而不是固定等待，機器忙碌時才不會誤判）；`run(want, during, max)` 編譯 `exampleCode()`、設定 `SIM.flashed`、呼叫 `startProgram()`，用 `hooks.serial` 收集輸出，直到所有正規表達式都符合；`spin(ms)` 一邊等一邊呼叫 `stepperTick()`。

涵蓋的範圍：

- 開發板資料的完整性，以及全部 116 種晶片的建議接線、範例程式編譯與檢測。
- 接錯的情況：電壓錯誤、非 ADC 腳、I2C 位址衝突、編譯錯誤、未實作的 SDK 函式。
- 每一種 SDK 實際執行範例程式：GPIO、按鈕控制蜂鳴器、I2C 感測器、ADC、SPI 熱電偶與 Flash、CAN 收發。
- 每一種溫度感測器型號、BMP280 補償公式、CRC-8、`cfmt()` 的格式化。
- 協定波形的編碼與解碼（含 300 組隨機 CAN 訊框）、四種分析儀的解碼與診斷。
- 步進馬達：微步編碼、線圈電流、六種 SDK 的計時器 PWM、微步與轉速、失步；TB67S128FTG 的每一種接錯行為。
- 分享網址的編碼與還原、每一關的準備與判定。

執行方式：

```text
npm test                                                   # 全部
node --test --test-name-pattern="printf" tests/core.test.js   # 只跑名稱符合的測試
npm run lint
npm run check                                              # lint + test + build
```

測試會實際等程式執行（`setTimeout` 與 `performance.now()`），整套在本機跑大約 70 秒。核心是單例，所以每個測試都要先 `setup()`；`resetBench()` 不會重設 `hooks` 與 `SIM`，測試裡改了它們，後面的測試會看到。

除錯時，因為核心沒有 DOM，可以寫一個小的 Node 腳本 import `compile()`，印出 `compile(src).js` 看轉譯結果（第 2.7 節的範例就是這樣產生的），或 import `runChecks()` 檢查某種接法。

## 6. 建置與部署

- `npm run build` 用 Vite 建置到 `dist/`（`target: 'es2020'`）。
- `npm run build:single` 先建置，再執行 `scripts/build-single.mjs`：把 `dist/index.html` 引用的 CSS 與 JS 內嵌成一個檔案 `dist-single/index.html`，刪掉 icon、manifest、apple-touch-icon 的連結；還有沒內嵌的 `assets/` 參照時丟出錯誤。註解說明用途是方便在沒有伺服器的地方預覽或分享。Google Fonts 的連結不在內嵌範圍內。
- `dist/` 與 `dist-single/` 都在 `.gitignore` 裡。
- `src/ui/guide.js` 用 Vite 的 `?raw` 匯入 `docs/` 裡的說明文件（包括這一份），所以文件會被打包進網站；改了文件要重新建置，網站裡看到的才會更新。

部署是 `.github/workflows/deploy.yml`：推送到 `main`（或手動 `workflow_dispatch`）時，用 Node 22 依序執行 `npm ci`、`npm run lint`、`npm test`、`npm run build`，再把 `dist` 上傳並部署到 GitHub Pages。檔案開頭的註解提醒：第一次使用要到 GitHub 專案的 Settings → Pages → Source 選「GitHub Actions」。

`src/config.js` 的 `CONFIG` 有兩個選用設定，都留空時不會載入任何外部程式：

- `goatcounter`：GoatCounter 的代碼。`ui/analytics.js` 只有在這裡有值、而且網址是 `https:` 時才載入統計腳本；`track(name)` 記錄事件，例如 `flash`、`share`、`open-shared`，以及 `start-`、`done-` 開頭、帶關卡 id 的事件。
- `signupUrl`：「有新關卡時通知我」的報名表網址，`ui/learn.js` 有值時才在學習地圖下方顯示按鈕。

Service worker 的歷史：網站以前有離線快取，但在 iPhone Safari 上 service worker 接手網頁請求時會讓網站打不開（「網路連線中斷」），所以停用了。現在的 `public/sw.js` 是刻意保留的關閉開關：安裝後清掉所有快取、註銷自己、重新載入已開啟的分頁，而且刻意不處理 `fetch`，所有請求都直接走網路。目前沒有任何程式註冊它。另外：

- `main.js` 啟動時會註銷所有已註冊的 service worker，並刪除名稱以 `mcu-lab` 開頭的快取。
- `index.html` 的啟動保護腳本不依賴任何外部檔案：超過 15 秒 `window.__mcuReady` 還沒被設定（有錯誤時是 4 秒），就顯示原因與「重新整理」「清除快取後重新整理」「重設工作台」三個按鈕。`main.js` 的 `boot()` 完成主要的初始化後設定 `window.__mcuReady = true`。
- `main.js` 用 `safely()` 包住闖關、說明文件、統計與 service worker 清理，註解說明選用功能出錯也不影響 3D 畫面。

## 7. 已知限制與注意事項

以下每一項都可以在程式碼、程式碼註解或 README 裡找到根據：

- 這不是真的交叉編譯器，是把 C 轉成 async JavaScript。指標運算、`struct`、`union` 還不支援（README）。型別不會截斷數值，只有明確的整數轉型會（見 2.7）。
- ADC 是簡化模型：`hadc1` 讀第一支接了類比訊號的 ADC 腳（`adcRead()` 的註解與 README）。
- STM32 HAL 的 I2C 只接了 `I2C1`，用其他控制代碼會回傳 `HAL_ERROR`（`hal.js` 的註解「模擬器只接了 I2C1」）。
- 匯流排速率固定：I2C 100 kHz、UART 115200 bps、SPI 1 MHz 模式 0、CAN 500 kbps（README 與 `trace.js` 的預設參數）。ST 的計時器 PWM 假設計時器時脈是 1 MHz。
- CAN 只模擬標準格式的資料訊框，對端是收發器模組內建的測試節點。部分 LPC55／LPC54 晶片有 CAN FD（MCAN 周邊），但它們的 `noCan` 寫明模擬器目前還沒有支援。
- MSP430FR2433、FR2311、FR6989 與 LPC800 系列沒有設定 STEP 輸出（各自的 `noStep`）。
- 轉子是簡化的力學模型，數值是示意用，不是特定馬達的實測曲線（README）。分頁在背景太久時，`advance()` 只補最近 1 秒。
- 訊號只有在工作台上有分析儀時才記錄，最多保留 12 秒。
- 編譯結果的 `size`、`ui/build.js` 印出的工具鏈指令（`toolchain()` 的註解寫「顯示用」）與燒錄過程的訊息都是模擬出來的。
- 所有資料只存在使用者瀏覽器的 `localStorage`；分享網址的內容只在 `#` 後面，不會送到伺服器（README）。
- `hooks.stepperOpened` 只有宣告，目前沒有使用。
