# MCU 模擬實驗室：範例程式解說

這份說明寫給正在學 MCU 程式的人。你在 [MCU 模擬實驗室](https://ken36789.github.io/stm32-sim/) 選好開發板、加上模組，按「建議接線」、再到「程式」分頁按「載入範例程式」，就會看到一支完整的 `main.c`。下面一段一段說明這支程式在做什麼、為什麼要這樣寫、在模擬器裡會看到什麼，以及最常見的錯誤。

> 這份說的是模擬器產生的 C 程式。想了解這個網站本身是怎麼寫的（模擬核心、3D、介面），請看 [原始碼導讀](原始碼導讀.md)。

## 1. 這份說明怎麼用

### 範例程式從哪裡來

- 「載入範例程式」會依照**目前的開發板、模組和接線**當場產生程式。產生器在 `src/core/codegen.js`，各家 SDK 的寫法在 `src/core/sdk.js`。
- 模組已經接好線的，程式就用它實際接到的腳位；還沒接線的，用「建議接線」會接的腳位。所以「先接線再載入程式」或「先載入程式再按建議接線」，結果都會一致。
- 只要你還沒修改編輯器裡的範例，之後換開發板、加減模組或改接線，範例會自動重新產生。你一旦改過程式，它就不會再被覆蓋，想要新的範例就再按一次「載入範例程式」。
- 「建議接線」會先拔掉所有的線再重新接。它會避開虛擬序列埠、板載 LED、I2C 的腳和板載按鈕的腳；I2C、SPI、CAN、STEP 這些有固定功能的腳，則一定接到這塊板子設定好的位置。

### 這份說明的程式片段

所有程式片段都是從模擬器實際產生的輸出複製來的，每段下面會註明是用哪一塊板子和哪些模組產生的。大部分用預設的開發板 **NUCLEO-H743ZI2**（STM32Cube HAL）。換成別的板子時，腳位名稱和 SDK 函式會不一樣，但程式的結構相同；第 4 節有六種 SDK 的對照表。

### 對照 3D 畫面看程式

程式最上面每一行 `#define` 的註解是對照的關鍵。例如第 2 節範例裡，外接 LED 那一行的註解是「LED（WP7113SRC/D） SIG → D2（PF15）」：

- `LED` 是模組名稱，括號裡是型號；`SIG` 是模組上的腳位名稱。
- `D2` 是開發板排針上印的名字。在 3D 畫面把滑鼠移到金色腳位上，會顯示這個名字、腳位功能和已經接到哪裡。
- `PF15` 是晶片本身的腳位名稱（GPIO 埠 F 的第 15 支腳），程式裡寫成 `GPIOF` 和 `GPIO_PIN_15`。
- 「接線」分頁下方的「排針腳位」表把排針名稱和晶片腳位並排列出來。接線檢測的訊息和「序列埠」分頁的「GPIO 即時狀態」都用晶片腳位名稱（例如 PF15），旁邊會標出這支腳現在是輸出還是輸入、是高電位 H 還是低電位 L。

### 實驗流程

面板上方的三個步驟一定要照順序：① 接線檢測 ② 編譯 ③ 燒錄。更換晶片、模組、型號、接線或修改程式之後，執行中的程式會停止，要重新檢測、編譯、燒錄。邏輯分析儀是例外：它只是量測儀器，接上或移除都不需要重新燒錄，範例程式也不會因為多了分析儀而改變。

## 2. 一支範例程式的骨架

先看一支完整但很短的範例。

```c
/* main.c — 由模擬器依目前的開發板與模組產生
 * 晶片：STM32H743ZIT6（Cortex-M7，480 MHz）
 * 開發板：NUCLEO-H743ZI2
 * SDK：STM32Cube HAL；printf 經由 USART3 輸出到虛擬序列埠（115200 bps）
 */
#include "main.h"
#include <stdio.h>

#define LD1_Port       GPIOB   // 板載 LD1
#define LD1_Pin        GPIO_PIN_0
#define LD2_Port       GPIOE   // 板載 LD2
#define LD2_Pin        GPIO_PIN_1
#define LD3_Port       GPIOB   // 板載 LD3
#define LD3_Pin        GPIO_PIN_14
#define B1_Port        GPIOC   // 板載按鈕 B1
#define B1_Pin         GPIO_PIN_13
#define LED_EXT_Port   GPIOF   // LED（WP7113SRC/D） SIG → D2（PF15）
#define LED_EXT_Pin    GPIO_PIN_15
#define BTN_Port       GPIOE   // 按鈕（Omron B3F-1000） OUT → D3（PE13）
#define BTN_Pin        GPIO_PIN_13
#define BUZZER_Port    GPIOF   // 蜂鳴器（TMB12A03） SIG → D4（PF14）
#define BUZZER_Pin     GPIO_PIN_14

int main(void)
{
  HAL_Init();
  SystemClock_Config();            // SYSCLK 480 MHz
  MX_GPIO_Init();
  MX_USART3_UART_Init();

  printf("\r\nNUCLEO-H743ZI2 啟動\r\n");

  uint32_t tick = 0;
  while (1)
  {
    tick++;
    if (tick % 50 == 0) {                 // 每 500 ms
      HAL_GPIO_TogglePin(LD1_Port, LD1_Pin);   // 板載 LD1
      HAL_GPIO_TogglePin(LED_EXT_Port, LED_EXT_Pin);
    }

    int btn = (HAL_GPIO_ReadPin(BTN_Port, BTN_Pin) == GPIO_PIN_SET);
    HAL_GPIO_WritePin(BUZZER_Port, BUZZER_Pin, (btn) ? GPIO_PIN_SET : GPIO_PIN_RESET);   // 按下按鈕（或偵測到人）時響
    HAL_GPIO_WritePin(LD3_Port, LD3_Pin, ((HAL_GPIO_ReadPin(B1_Port, B1_Pin) == GPIO_PIN_SET)) ? GPIO_PIN_SET : GPIO_PIN_RESET);   // 板載 B1 → LD3

    if (tick % 100 == 0) {                // 每秒回報一次
      printf("運作中，第 %u 秒\r\n", tick / 100);
    }

    HAL_Delay(10);
  }
}
```

以 NUCLEO-H743ZI2＋LED＋按鈕＋蜂鳴器（TMB12A03）產生

### 開頭註解與 include

開頭註解寫出晶片型號、核心、時脈、開發板、使用的 SDK，以及 `printf` 從哪個 UART 送到虛擬序列埠。有用到 SPI、CAN 或步進馬達時，這裡會多一行寫出用的是哪一組周邊和哪幾支腳。換板子之後先看這裡，就知道程式是給哪顆晶片寫的。

`main.h` 是 STM32CubeIDE 專案的主要標頭檔，HAL 函式庫從這裡引入；`<stdio.h>` 是 `printf` 的宣告。其他 SDK 會換成自己的標頭檔，例如 MSPM0 是 SysConfig 產生的 `ti_msp_dl_config.h`，MCUXpresso 是 `fsl_gpio.h`、`fsl_debug_console.h` 這一類。

### #define 腳位對照

每一個用到的腳位都取一個名字。HAL 的一支腳要兩個資訊：埠（`GPIOF`）和腳位遮罩（`GPIO_PIN_15`），所以每個名字有 `_Port` 和 `_Pin` 兩行。之後程式只寫 `LED_EXT_Port`、`LED_EXT_Pin`，要換腳時只改這兩行就好。

板載 LED 和按鈕（LD1、LD2、LD3、B1）不論有沒有用到都會定義；外接模組只有接上了才會出現。

### 初始化順序

1. `HAL_Init()`：初始化 HAL 函式庫，包括 `HAL_Delay` 用的 1 ms 時基。
2. `SystemClock_Config()`：設定系統時脈。UART 的鮑率、計時器的頻率都是從系統時脈分出來的，所以要最先做。
3. `MX_GPIO_Init()`：設定每支腳是輸入還是輸出。
4. 各個周邊的 `MX_..._Init()`：有 I2C 感測器時是 `MX_I2C1_Init()`，有旋鈕時是 `MX_ADC1_Init()`，最後一定有序列埠的 `MX_USART3_UART_Init()`；用到 SPI、CAN、步進馬達時接著是它們的初始化。
5. 把 SPI 元件的 CS 先拉高、把驅動板的 STANDBY、ENABLE 拉高（有這些模組時才會有）。
6. 先印出「啟動」，再初始化外部元件（例如 `TEMP_Init()`）。這樣就算元件沒有回應，你也看得到程式確實有在跑。

> `MX_` 開頭的函式在真的 STM32CubeIDE 專案裡，是 STM32CubeMX 依你的腳位與周邊設定自動產生的。模擬器把它們當成空函式（`src/core/hal.js` 裡是 noop），所以在模擬器裡不用設定；但拿到真的板子上，CubeMX 的設定一定要和 `#define` 的腳位一樣。

### 主迴圈與 tick

MCU 的程式通常不會結束：`while (1)` 會一直重複。範例的迴圈只有一個延遲，放在最後面：`HAL_Delay(10)`。所以每跑一圈大約 10 ms，`tick` 每圈加 1，等於一個「每 10 ms 加一」的計數器。要讓某件事每隔一段時間做一次，就看 `tick` 除以某個數的餘數是不是 0：

| 寫法 | 多久成立一次 | 範例拿來做什麼 |
| --- | --- | --- |
| 每一圈都做 | 每 10 ms | 讀按鈕、控制蜂鳴器、接收 CAN、更新步進馬達速度 |
| `tick % 10 == 0` | 每 100 ms | 有兩顆馬達和旋鈕時，讀旋鈕決定 M2 的目標速度 |
| `tick % 50 == 0` | 每 500 ms | LED 切換一次（亮 0.5 秒、暗 0.5 秒） |
| `tick % 100 == 0` | 每 1 秒 | 序列埠回報、讀感測器、送出 CAN、檢查驅動板錯誤旗標 |
| `tick % 200 == 0` | 每 2 秒 | 繼電器切換 |
| `(tick % 300) < 10` | 每 3 秒的前 100 ms | 沒有按鈕時，蜂鳴器每 3 秒嗶一聲 |

`tick / 100` 就是開機後經過的秒數，所以序列埠會印出「運作中，第 1 秒」、「第 2 秒」……

為什麼不用 `HAL_Delay(500)` 來閃 LED？因為延遲的時候 CPU 什麼都不做，按鈕要等 0.5 秒才會被讀到一次。改成「短延遲＋計數」，每件事都能用自己的節奏進行，按鈕每 10 ms 就檢查一次，按下去感覺是即時的。

在真的晶片上，迴圈裡的工作（例如 I2C 讀取）也要花時間，所以一圈會比 10 ms 多一點。模擬器的延遲是從「上一次延遲應該結束的時間」起算，扣掉模擬器自己花的時間，所以平均剛好 10 ms，步進馬達用固定 0.01 秒算出來的位置才會和實際送出的脈波一致。

## 3. 各功能的程式

### 3.1 GPIO 輸出：LED

```c
    if (tick % 50 == 0) {                 // 每 500 ms
      HAL_GPIO_TogglePin(LD1_Port, LD1_Pin);   // 板載 LD1
      HAL_GPIO_TogglePin(LED_EXT_Port, LED_EXT_Pin);
    }
```

以 NUCLEO-H743ZI2＋LED＋按鈕＋蜂鳴器產生

**程式在做什麼**：GPIO（General Purpose Input/Output，通用輸入輸出腳）設成輸出時，程式可以讓它變成高電位（3.3 V）或低電位（0 V）。`HAL_GPIO_TogglePin` 把目前的電位反過來，每 500 ms 反一次，LED 就一秒閃一下。要直接指定亮或暗時用 `HAL_GPIO_WritePin(..., GPIO_PIN_SET)` 或 `GPIO_PIN_RESET`。

**硬體原理**：LED 模組的 SIG 是「高電位點亮」，模組裡已經有限流電阻。GPIO 輸出高電位時，電流從 SIG 經過 LED 流到 GND 再回到開發板，所以 LED 的 GND 一定要接到開發板的 GND，這叫「共地」。沒有回路就沒有電流，程式再怎麼寫 LED 都不會亮。

**低電位點亮的板載 LED**：有些開發板的 LED 是接在 3.3 V 和 GPIO 之間，GPIO 輸出低電位才會亮。範例會在 `#define` 的註解標出「（低電位點亮）」，並且在程式裡把條件反過來。例如 FRDM-K64F 的三顆板載 LED 都是低電位點亮：

```c
    int btn = (GPIO_PinRead(BTN_GPIO, BTN_PIN) == 1U);
    GPIO_PinWrite(LEDG_GPIO, LEDG_PIN, (!(btn)) ? 1U : 0U);   // 外接按鈕 → LEDG
```

以 FRDM-K64F＋LED＋按鈕產生（MCUXpresso SDK）

按下按鈕時 `btn` 是 1，`!(btn)` 是 0，輸出低電位，綠色 LED 亮。

**在模擬器裡會看到**：3D 畫面上外接 LED 和板載 LD1 一起閃；「序列埠」分頁的「GPIO 即時狀態」裡 PF15 在 H 和 L 之間切換。

**常見錯誤**：

- LED 的 GND 沒接：檢測顯示「LED 的 GND 沒有接地」。
- SIG 沒接：「LED SIG 沒有接」。
- SIG 接的腳和 `#define` 不一樣，例如接到 D7：「程式沒有控制 PF13」。改接線，或重新按「載入範例程式」讓程式跟著接線走。

**對應關卡**：闖關 1「點亮外接 LED」、故障挑戰 1「LED 不會亮」。

### 3.2 GPIO 輸入：按鈕

```c
    int btn = (HAL_GPIO_ReadPin(BTN_Port, BTN_Pin) == GPIO_PIN_SET);
    HAL_GPIO_WritePin(BUZZER_Port, BUZZER_Pin, (btn) ? GPIO_PIN_SET : GPIO_PIN_RESET);   // 按下按鈕（或偵測到人）時響
    HAL_GPIO_WritePin(LD3_Port, LD3_Pin, ((HAL_GPIO_ReadPin(B1_Port, B1_Pin) == GPIO_PIN_SET)) ? GPIO_PIN_SET : GPIO_PIN_RESET);   // 板載 B1 → LD3
```

以 NUCLEO-H743ZI2＋LED＋按鈕＋蜂鳴器產生

**程式在做什麼**：`HAL_GPIO_ReadPin` 讀腳位現在的電位，和 `GPIO_PIN_SET`（高電位）比較，得到 1（按下）或 0（放開）。每 10 ms 讀一次，讀到的結果直接拿去控制蜂鳴器；板載按鈕 B1 則直接控制 LD3。這就是嵌入式程式最基本的「輸入 → 判斷 → 輸出」。

**硬體原理：上拉與下拉電阻**：輸入腳如果什麼都沒接，電位是不確定的（叫「浮接」），讀起來可能忽 0 忽 1。所以按鈕電路一定會配一個電阻，在按鈕放開時把腳位固定在某個電位：

- **下拉電阻**：電阻接到 GND，放開時是低電位，按下時按鈕把腳接到 VCC，變成高電位。外接按鈕模組就是這種，模組上的說明寫著「按下為高電位（內含 10 kΩ 下拉）」。
- **上拉電阻**：電阻接到 VCC，放開時是高電位，按下時按鈕把腳接到 GND，變成低電位。很多開發板的板載按鈕是這種，範例會在註解寫「（按下為低電位）」，判斷時加上 `!`。

有些 SDK 要在程式裡自己打開晶片內建的上拉或下拉電阻。例如 MSP430 的板載按鈕 S1（註解寫「按下為低電位」）用上拉、外接按鈕用下拉：

```c
  GPIO_setAsInputPinWithPullUpResistor(S1_PORT, S1_PIN);
  GPIO_setAsOutputPin(LED_EXT_PORT, LED_EXT_PIN);
  GPIO_setAsInputPinWithPullDownResistor(BTN_PORT, BTN_PIN);
```

以 MSP-EXP430FR2355＋LED＋按鈕產生（MSP430 DriverLib）

**只在按下的那一瞬間做事**：有時候你想要「按一下印一次」，而不是按住時一直印。範例在板子只有一顆板載 LED 時會這樣寫：

```c
    int user = (HAL_GPIO_ReadPin(B1_Port, B1_Pin) == GPIO_PIN_SET);
    if (user && !userLast) printf("B1 被按下\r\n");
    userLast = user;
```

以 NUCLEO-F401RE＋LED＋按鈕產生

`userLast` 記住上一圈的狀態。「這一圈是按下、上一圈是放開」只會在按下的那一瞬間成立一次，這叫偵測「上升緣」。

> 在 NUCLEO-F401RE 這種只有一顆板載 LED、又沒有蜂鳴器的組合，範例只讀外接按鈕（`btn`），沒有拿它做任何事。可以自己加上動作，例如用 `btn` 控制外接 LED。另外，真的按鈕按下時接點會彈跳幾毫秒（元件資訊頁寫著 B3F 約 5 ms），自己寫「按一次算一次」的程式時要記得這件事。

**在模擬器裡會看到**：在 3D 畫面長按按鈕模組的黑色按鍵，或到「元件」分頁點按鈕、按住「按住這裡＝按下按鈕」。板載 B1 也可以在 3D 畫面上按住。

**常見錯誤**：

- OUT 接到別的腳：「程式沒有讀取 PG9」（腳位名稱看你實際接到哪裡）。
- 按鈕 VCC 接 5V：「按鈕 的 VCC 接到 5V」，按下時會把 5 V 送進 GPIO，有些腳不耐 5 V。

**對應關卡**：闖關 2「按鈕控制蜂鳴器」、故障挑戰 2「按鈕按了沒反應」。

### 3.3 蜂鳴器

有按鈕時，蜂鳴器跟著按鈕響（上一節的程式）。沒有按鈕時，範例讓它每 3 秒嗶一聲：

```c
    HAL_GPIO_WritePin(BUZZER_Port, BUZZER_Pin, ((tick % 300) < 10) ? GPIO_PIN_SET : GPIO_PIN_RESET);   // 每 3 秒嗶一聲
```

以 NUCLEO-H743ZI2＋蜂鳴器（TMB12A03）產生

**硬體原理**：模擬器用的是「有源蜂鳴器」，裡面已經有震盪電路（約 2.3 kHz），只要 SIG 是高電位就會響，所以程式用一般的 GPIO 輸出就能控制，不需要 PWM。`(tick % 300) < 10` 在每 300 圈（3 秒）的前 10 圈（100 ms）成立，所以是「嗶」一聲短音。

**在模擬器裡會看到**：右上角「聲音」打開以後，按住按鈕就聽得到聲音。

**常見錯誤**：用 TMB12A05 時檢測會提示「蜂鳴器 用 3.3 V 驅動」：3.3 V 下還是會響，只是比較小聲；換成 TMB12A03 會比較大聲。這只是提示，不擋燒錄。

**對應關卡**：闖關 2「按鈕控制蜂鳴器」。

### 3.4 其他 GPIO 模組：PIR 與繼電器

- **PIR（人體紅外線感應）**：偵測到人時 OUT 輸出高電位一段時間。範例用和 3.2 節一樣的上升緣寫法（`pir && !pirLast`），有人經過時印一次「PIR：偵測到有人經過」。在「元件」分頁按「模擬有人經過」試試看。HC-SR501 要接 5V 才會正常偵測（輸出仍是 3.3 V）。
- **繼電器**：IN 高電位時線圈通電、接點吸合。範例在 `tick % 200 == 0` 時用 `HAL_GPIO_TogglePin` 切換，每 2 秒切換一次。線圈的電壓要符合型號：5 V 的繼電器接 3.3 V 吸不動，檢測會顯示「繼電器（5 V 繼電器模組） 的 VCC 只有 3.3 V」（故障挑戰 6「繼電器吸不動」）。

### 3.5 類比輸入：旋鈕與 ADC

初始化時多了一行 `MX_ADC1_Init();`，主迴圈每秒讀一次：

```c
    if (tick % 100 == 0) {                // 每秒回報一次
      {
        HAL_ADC_Start(&hadc1);
        HAL_ADC_PollForConversion(&hadc1, 10);
        uint32_t adc = HAL_ADC_GetValue(&hadc1);
        printf("類比 ADC = %4lu (%.2f V)\r\n", adc, adc * 3.3f / 4095.0f);
      }
    }
```

以 NUCLEO-H743ZI2＋類比輸入模組（10 kΩ 旋轉電位器）產生

**程式在做什麼**：ADC（Analog-to-Digital Converter，類比數位轉換器）把腳位上的電壓換成一個數字。三個步驟：`HAL_ADC_Start` 開始轉換、`HAL_ADC_PollForConversion` 等它轉換完（最多等 10 ms）、`HAL_ADC_GetValue` 取出結果。

**換算電壓**：12 位元的 ADC 把 0 到 3.3 V 分成 4096 階，0 V 讀到 0，3.3 V 讀到 4095，所以電壓 ＝ 讀值 × 3.3 ÷ 4095。模擬器裡有 4 塊 MSP430 板子（FR2433、FR2311、FR4133、FR5739）是 10 位元，範例會自動改成除以 1023。

**硬體原理**：電位器（旋鈕）是一個可以調整的分壓電路，OUT 的電壓在 0 V 到 VCC 之間。所以 VCC 要接 3V3：如果接 5V，轉到三分之二以上 OUT 就超過 3.3 V，ADC 只能讀到最大值，還可能傷到腳位。另外不是每一支腳都有 ADC 功能，OUT 一定要接到類比輸入腳（Nucleo 板上是 A0、A1 這些 A 開頭的腳；「接線」分頁的「排針腳位」表會標出「ADC 類比輸入」）。

**printf 不印小數的版本**：MSP430、TivaWare、MCUXpresso 的範例不用 `%f`，而是換算成毫伏特再用整數印出來（嵌入式的精簡版 printf 常常不支援浮點數）：

```c
        printf("類比 ADC = %4u（%u mV）\r\n", adc, (uint32_t)(adc * 3300 / 4095));
```

以 MSP-EXP430FR2355＋LED＋按鈕＋旋鈕＋BME280＋TB67S128FTG＋馬達＋24 V 電源產生

**在模擬器裡會看到**：到「元件」分頁點旋鈕，拖曳「旋鈕位置」滑桿；序列埠每秒印一次讀值和電壓。

> 模擬器的 ADC 是簡化模型：`hadc1`（以及其他 SDK 的 ADC 讀值函式）讀的是第一個接了類比模組的 ADC 腳，所以範例不用另外選通道。

**常見錯誤**：

- VCC 接 5V：「類比（10 kΩ 旋轉電位器） 的 VCC 接到 5 V」。
- OUT 接到沒有 ADC 的腳，例如 D7：「類比 OUT 接到 D7（PF13）」。
- 程式裡沒有讀 ADC：「程式沒有讀取 ADC」。

**對應關卡**：闖關 3「旋鈕和 ADC」、故障挑戰 3「旋鈕轉到一半就卡住」。

### 3.6 I2C 溫度感測器（以 BME280 為例）

I2C 只用兩條線：SCL（時脈）和 SDA（資料）。同一組線上可以掛很多元件，每個元件有自己的「位址」。MCU 先送出位址，位址對的元件會回一個 ACK（確認），然後才開始傳資料；沒有元件回應就是 NACK。

```c
#define TEMP_ADDR      0x76   // 感測器（Bosch BME280），7 位元 I2C 位址

static int I2C_Write(uint8_t addr, uint8_t *data, int len)
{
  return HAL_I2C_Master_Transmit(&hi2c1, addr << 1, data, len, 100) == HAL_OK;
}

static int I2C_Read(uint8_t addr, uint8_t *buf, int len)
{
  return HAL_I2C_Master_Receive(&hi2c1, addr << 1, buf, len, 100) == HAL_OK;
}

static int I2C_ReadReg(uint8_t addr, uint8_t reg, uint8_t *buf, int len)
{
  uint8_t r[1];
  r[0] = reg;
  if (!I2C_Write(addr, r, 1)) return 0;
  return I2C_Read(addr, buf, len);
}
```

以 NUCLEO-H743ZI2＋I2C 溫度感測器（BME280）產生

**三個小函式**：

- `I2C_Write`、`I2C_Read`：寫入或讀出幾個位元組，成功回傳 1。這兩個是各家 SDK 寫法不同的地方。
- `I2C_ReadReg`：讀某個「暫存器」（感測器裡的一格資料）。先寫入暫存器編號，再讀回資料。
- 位址為什麼要 `addr << 1`：I2C 的位址是 7 位元，傳輸時後面會再接 1 位元表示讀或寫。HAL 的函式要你給「左移一位」之後的 8 位元值，其他 SDK（MSPM0、MSP430、TivaWare、C2000、MCUXpresso）的範例直接給 7 位元位址。

感測器本身的驅動程式（下面的 `TEMP_Init`、`TEMP_Read`）只透過這三個函式和感測器溝通，所以六種 SDK 共用同一份。

```c
static int TEMP_Init(void)
{
  uint8_t id[1];
  uint8_t c[6];
  uint8_t mode[2] = {0xF4, 0x27};        // ctrl_meas：溫度、氣壓各取樣 1 次，正常模式
  if (!I2C_ReadReg(TEMP_ADDR, 0xD0, id, 1)) return 0;
  printf("Bosch BME280 晶片 ID = 0x%02X\r\n", id[0]);
  I2C_Write(TEMP_ADDR, mode, 2);
  I2C_ReadReg(TEMP_ADDR, 0x88, c, 6);       // 校正值 dig_T1..T3
  TEMP_T1 = c[0] | (c[1] << 8);
  TEMP_T2 = (int16_t)(c[2] | (c[3] << 8));
  TEMP_T3 = (int16_t)(c[4] | (c[5] << 8));
  return 1;
}
```

以 NUCLEO-H743ZI2＋I2C 溫度感測器（BME280）產生

**初始化在做什麼**：

1. 讀暫存器 0xD0 的晶片 ID。讀得到代表接線和位址都對（BME280 是 0x60、BMP280 是 0x58）。讀不到就回傳 0，`main` 會印「感測器（Bosch BME280）沒有回應，請檢查接線」。
2. 寫 0xF4 ＝ 0x27，讓感測器開始量測。
3. 從 0x88 讀出出廠時存在晶片裡的校正值（每顆不一樣）。低位元組在前，所以用 `c[0] | (c[1] << 8)` 拼成 16 位元。

`TEMP_Read()` 從 0xFA 讀 3 個位元組，拼成 20 位元的原始值，再用 datasheet 的整數補償公式和校正值算出溫度（°C）。讀取失敗時回傳 -999.0；主迴圈每秒呼叫一次，結果大於 -100 就印「感測器 溫度 = … °C」，否則印「感測器 讀取失敗」。

**其他型號**：模擬器有 8 種 I2C 溫度感測器，都接在同一組 SCL、SDA 上，各有自己的位址：LM75A 和 TMP102 是 0x48（兩顆位址相同，不能同時接）、MCP9808 是 0x18、BMP280 和 BME280 是 0x76、AHT20 是 0x38、HDC1080 是 0x40、SHT31 是 0x44。AHT20 和 SHT31 的範例會同時印出溼度。

**在模擬器裡會看到**：序列埠先印晶片 ID，之後每秒一筆溫度。在 3D 畫面點感測器上的小晶片（等於用手指按住），溫度會往上升；「元件」分頁可以調環境溫度。接上 I2C 分析儀可以看到 START、位址、ACK、資料、STOP。

**常見錯誤**：

- SCL、SDA 接反：「感測器 的 SCL 與 SDA 接反」。I2C 的腳是固定的，NUCLEO-H743ZI2 的 SCL 在 D15（PB8）、SDA 在 D14（PB9）。
- 程式裡的位址寫錯：接線檢測全部通過，序列埠卻印「沒有回應，請檢查接線」。對照「元件」分頁的規格，BME280 模組是 0x76。
- 兩顆同位址的感測器：「I2C 位址衝突：0x48」。
- 3.6 V 的感測器接 5V：「感測器（BME280 溫溼度／氣壓） 的 VCC 接到 5 V」，通電後感測器會損壞，要在檢測裡換一顆新的。
- 感測器接好了，程式卻沒有呼叫 I2C：「程式沒有使用 I2C」。
- 模擬器的 HAL 只接了 I2C1，程式要用 `hi2c1`。

**對應關卡**：闖關 4「I2C 溫度感測器」、故障挑戰 4「溫度讀取失敗（接線）」、故障挑戰 5「溫度讀取失敗（程式）」。

### 3.7 UART 與序列埠：printf

範例裡的每一個 `printf`（例如第 2 節的「啟動」和「運作中，第 … 秒」）都會經過 UART（通用非同步收發器）送到開發板上的除錯器，再變成電腦上的「虛擬序列埠」。模擬器的「序列埠」分頁就是這個視窗，上方寫著 `USART3 · ST-LINK V3E 虛擬序列埠 · 115200 8N1`。

- **115200 8N1**：每秒 115200 個位元（鮑率），8 個資料位元、沒有同位檢查位元、1 個停止位元。兩邊的鮑率一定要一樣，不然收到的是亂碼。
- **`\r\n`**：回到行首再換行。序列埠終端機大多要兩個都送才會正確換行。
- **各家的輸出函式**：HAL、MSPM0、MSP430、C2000 用 `printf`；TivaWare 用 `UARTprintf`，要先呼叫 `UARTStdioConfig`；MCUXpresso 用 `PRINTF`，由 `BOARD_InitDebugConsole()` 設定。

不支援 `%f` 的 SDK，溫度會先乘 100 變成整數，再分成整數部分和小數部分印出：

```c
          int t100 = (int)(t * 100.0f);
          UARTprintf("感測器 溫度 = %d.%02d °C\r\n", t100 / 100, abs(t100 % 100));
```

以 EK-TM4C123GXL＋LED＋按鈕＋旋鈕＋BME280＋TB67S128FTG＋馬達＋24 V 電源產生（TivaWare）

**用邏輯分析儀看 UART**：加上「UART 分析儀」，TX 探棒接 MCU 的 TX（NUCLEO-H743ZI2 是 PD8），GND 接開發板的 GND。點 3D 畫面上的分析儀打開波形：UART 平常是高電位；起始位元先拉低一個位元時間，接著 8 個資料位元（低位元先送），最後停止位元回到高電位。115200 bps 時一個位元約 8.7 µs。把分析儀的鮑率故意改成 9600，就會看到解碼錯誤。

**常見錯誤**：

- 把模組接到序列埠的腳：「PD8 是虛擬序列埠腳位」，會干擾 printf。
- 分析儀沒有共地：「UART 分析 的 GND 沒有接」，波形會亂跳、解碼失敗。

**對應關卡**：闖關 5「用邏輯分析儀看 UART」。

### 3.8 SPI：熱電偶與 Flash

SPI 用四條線：SCK（時脈，由 MCU 送出）、MOSI（Master Out Slave In，MCU 送給元件的資料）、MISO（Master In Slave Out，元件回給 MCU 的資料）、CS（Chip Select，片選）。前三條所有元件共用，CS 每個元件各一條，**低電位代表選中**。SPI 是「一邊送一邊收」：MCU 送出幾個位元組，就同時收回幾個位元組。

兩個元件的 CS 各定義一組名字（`TC_CS`、`FLASH_CS`），註解寫著「（低電位選中）」。`SPI_Xfer` 包住 SDK 的傳輸函式，熱電偶的讀取函式只用它和 CS：

```c
static void SPI_Xfer(uint8_t *tx, uint8_t *rx, int len)
{
  HAL_SPI_TransmitReceive(&hspi1, tx, rx, len, 100);
}

static float TC_Read(void)
{
  uint8_t tx[2] = {0x00, 0x00};
  uint8_t rx[2];
  HAL_GPIO_WritePin(TC_CS_Port, TC_CS_Pin, GPIO_PIN_RESET);   // CS 拉低：選中 MAX6675
  SPI_Xfer(tx, rx, 2);                   // MAX6675 只送資料，MOSI 送什麼都可以
  HAL_GPIO_WritePin(TC_CS_Port, TC_CS_Pin, GPIO_PIN_SET);   // CS 拉高：結束傳輸，晶片開始下一次轉換
  uint16_t v = (rx[0] << 8) | rx[1];
  if (v & 0x0004) return -999.0f;        // D2 = 1：熱電偶沒有接
  return (v >> 3) * 0.25f;               // D14..D3：溫度，每單位 0.25 °C
}
```

以 NUCLEO-H743ZI2＋SPI 熱電偶（MAX6675）＋SPI Flash（W25Q32JV）產生

**CS 為什麼由程式控制**：CS 就是一支普通的 GPIO。程式在傳輸前拉低（選中）、傳完拉高（結束）。兩個元件共用 SCK、MISO、MOSI，靠各自的 CS 分開；如果兩個同時被選中，兩邊會同時在 MISO 上回資料，互相干擾。所以初始化時先把所有 CS 拉高：

```c
  MX_SPI1_Init();                  // SPI1：模式 0、MSB 先送、約 1 MHz
  HAL_GPIO_WritePin(TC_CS_Port, TC_CS_Pin, GPIO_PIN_SET);   // 熱電偶 先不選中
  HAL_GPIO_WritePin(FLASH_CS_Port, FLASH_CS_Pin, GPIO_PIN_SET);   // Flash 先不選中
```

以 NUCLEO-H743ZI2＋SPI 熱電偶（MAX6675）＋SPI Flash（W25Q32JV）產生

第一個 SPI 元件的 CS 接開發板預設的 CS 腳（Nucleo-144 是 D10），第二個以後接一般 GPIO（這裡是 D2）。

**熱電偶**：熱電偶模組只送資料、不收指令，所以只有 SO（就是 MISO），MOSI 送 0x00 當作「推動時脈」用。讀回的位元在 datasheet 裡各有意義：

| 型號 | 一次讀幾位元 | 溫度在哪裡 | 斷線怎麼知道 |
| --- | --- | --- | --- |
| MAX6675 | 16 | D14..D3，每單位 0.25 °C | D2 ＝ 1 |
| MAX31855K | 32 | D31..D18（有號數，可以是負溫度）；D15..D4 是冷接點（晶片本身）溫度 | D16 ＝ 1 |

**SPI Flash**：Flash 是可以存資料、斷電也不會消失的記憶體。每個操作都由 `FLASH_Cmd()` 包成「CS 拉低 → 送指令和位址 → CS 拉高」，寫入和抹除在 CS 拉高的那一刻才開始。

```c
static int FLASH_Init(void)
{
  uint8_t id[4] = {0x9F, 0x00, 0x00, 0x00}; // 0x9F：讀 JEDEC ID
  uint8_t rx[4];
  uint8_t se[4] = {0x20, 0x00, 0x00, 0x00}; // 0x20：抹除位址 0 所在的 4 KB 磁區（全部變成 0xFF）
  uint8_t pp[12] = {0x02, 0x00, 0x00, 0x00, 0x4D, 0x43, 0x55, 0x2D, 0x4C, 0x61, 0x62, 0x21};   // 0x02：寫入 "MCU-Lab!"
  uint8_t dummy[12];
  FLASH_Cmd(id, rx, 4);
  printf("Winbond W25Q32JV JEDEC ID = %02X %02X %02X\r\n", rx[1], rx[2], rx[3]);
  if (rx[1] != 0xEF) return 0;           // 0xEF = Winbond
  FLASH_WriteEnable();
  FLASH_Cmd(se, dummy, 4);
  FLASH_WaitBusy();
  FLASH_WriteEnable();
  FLASH_Cmd(pp, dummy, 12);
  FLASH_WaitBusy();
  return 1;
}
```

以 NUCLEO-H743ZI2＋SPI 熱電偶（MAX6675）＋SPI Flash（W25Q32JV）產生

1. `0x9F` 讀 JEDEC ID：製造商、記憶體類型、容量。W25Q32JV 是 EF 40 16，W25Q128JV 是 EF 40 18。第一個位元組不是 0xEF 就當作沒接好。
2. `0x06` 允許寫入（`FLASH_WriteEnable`）：每次抹除或寫入之前都要送一次。
3. `0x20` 抹除 4 KB 磁區：Flash 的寫入只能把 1 變成 0，所以要先抹除（全部變回 0xFF）才能寫。
4. `0x05` 讀狀態（`FLASH_WaitBusy` 裡）：BUSY 位元是 1 代表抹除或寫入還沒做完，每 1 ms 問一次。
5. `0x02` 寫入：從位址 0 寫入 "MCU-Lab!" 這 8 個字元。

之後主迴圈每秒用 `0x03` 從位址 0 讀回 8 個位元組，印出十六進位和文字。

**在模擬器裡會看到**：序列埠印出 JEDEC ID，之後每秒印熱電偶溫度和 Flash 讀回的「MCU-Lab!」。「元件」分頁可以拖曳「熱電偶溫度」，或勾選「熱電偶斷線」看故障位元。接上 SPI 分析儀，解碼列會標出 Flash 的指令。

**常見錯誤**：

- Flash 的 DI、DO 接反：「Flash 的 DI 與 DO 接反」，讀到的全是 FF。DI（資料輸入）和 DO（資料輸出）是從 Flash 的角度命名的：DI 接 MCU 的 MOSI，DO 接 MISO。
- CS 接到 SCK、MISO 或 MOSI：「熱電偶 的 CS 接到 SPI 訊號腳」。
- 元件接好但程式沒有 SPI：「程式沒有使用 SPI」。
- MSP430FR2311、MSP430FR4133 沒有多的 SPI 可用，SPI 元件會變成灰色。

**對應關卡**：故障挑戰 7「Flash 讀出來全是 FF」。

### 3.9 CAN

CAN 是汽車和工業設備常用的匯流排。它用兩條線 CANH、CANL 的電壓差（差動訊號）傳資料，比較不怕雜訊。MCU 的 CAN 控制器只有 TX、RX 兩支邏輯腳，中間要經過「收發器」轉成差動訊號；匯流排兩端還要有 120 Ω 的終端電阻。模擬器的收發器模組已經內建終端電阻和一個「測試節點」：它每 500 ms 送出 ID 0x200 的訊框（內容是 2 位元組的計數值），也會對 MCU 送出的訊框回 ACK。

程式用 `CAN_TX_ID`（0x123）當作 MCU 自己送出的 ID，`CAN_RX_ID`（0x200）是測試節點的 ID。初始化：

```c
  MX_FDCAN1_Init();                // 傳統 CAN 500 kbps
  canTx.Identifier = CAN_TX_ID;
  canTx.IdType = FDCAN_STANDARD_ID;
  canTx.TxFrameType = FDCAN_DATA_FRAME;
  canTx.DataLength = FDCAN_DLC_BYTES_4;
  canTx.ErrorStateIndicator = FDCAN_ESI_ACTIVE;
  canTx.BitRateSwitch = FDCAN_BRS_OFF;
  canTx.FDFormat = FDCAN_CLASSIC_CAN;
  canTx.TxEventFifoControl = FDCAN_NO_TX_EVENTS;
  canTx.MessageMarker = 0;
  HAL_FDCAN_ConfigGlobalFilter(&hfdcan1, FDCAN_ACCEPT_IN_RX_FIFO0, FDCAN_ACCEPT_IN_RX_FIFO0, FDCAN_REJECT_REMOTE, FDCAN_REJECT_REMOTE);   // 接收所有 ID
  HAL_FDCAN_Start(&hfdcan1);
```

以 NUCLEO-H743ZI2＋CAN 收發器（SN65HVD230）產生

**程式在做什麼**：

1. 初始化時填好「要送出的訊框長什麼樣子」：標準格式（11 位元 ID）的資料訊框，ID 0x123，4 個位元組，傳統 CAN（不是 CAN FD）。

3. 每一圈（10 ms）檢查接收佇列，有幾筆就讀幾筆、印幾筆。
4. 每秒送出一筆：前兩個位元組是計數值（先送高位元組），後面是 0x00、0xFF。

**不同的 STM32 用不同的 CAN 周邊**：G4、H5、H7、U5 是 FDCAN（`HAL_FDCAN_` 開頭）；其他有 CAN 的 STM32 是 bxCAN（`HAL_CAN_` 開頭，送出用 `HAL_CAN_AddTxMessage`，F0、F1、F3 的 handle 是 `hcan`，F2、F4、F7、L4 是 `hcan1`）。TI、NXP 的寫法見第 4 節。116 種晶片裡有 60 種沒有 CAN（或模擬器還沒支援），CAN 模組會變成灰色。

**在模擬器裡會看到**：序列埠交替出現「CAN 送出 ID 0x123：計數 …」和「CAN 收到 ID 0x200：2 個位元組，計數 …」。接上 CAN 分析儀到 CANH、CANL，可以看到 SOF、ID、DLC、資料、CRC、ACK 和填充位元。

**常見錯誤**：

- TXD、RXD 接反：「CAN 的 TXD 與 RXD 接反」，序列埠只有「送出」沒有「收到」。收發器的 TXD 接 MCU 的 `CAN_TX`、RXD 接 `CAN_RX`，和 UART 的交叉接法不一樣。
- TJA1050 接 3V3：「CAN（TJA1050 CAN 收發器） 的 VCC 只有 3.3 V」，它要 5 V。按「建議接線」會自動接 5V。
- 收發器接好但程式沒有送訊框：「程式沒有使用 CAN」。

**對應關卡**：故障挑戰 8「CAN 沒有回應」。

### 3.10 計時器 PWM 與步進馬達的 STEP

步進馬達每收到一個 STEP 脈波就轉一小格（一個「微步」）。脈波一秒送幾個（pps，pulses per second）決定轉速，送了幾個決定轉了多遠。STEP 一秒要送好幾千到上萬個，所以範例用**計時器的硬體 PWM** 產生：設好頻率以後，計時器自己一直送，不佔用 CPU。

```c
static void M1_SetPps(uint32_t pps)
{
  if (pps < 16) { HAL_TIM_PWM_Stop(&htim4, TIM_CHANNEL_4); return; }   // 太慢（16 位元計時器的下限）就停止輸出
  uint32_t arr = 1000000 / pps - 1;                // 計時器時脈 1 MHz：頻率 = 1 MHz ÷ (ARR + 1)
  __HAL_TIM_SET_AUTORELOAD(&htim4, arr);
  __HAL_TIM_SET_COMPARE(&htim4, TIM_CHANNEL_4, arr / 2);     // 50% 責任週期
  HAL_TIM_PWM_Start(&htim4, TIM_CHANNEL_4);
}
```

以 NUCLEO-H743ZI2＋TB67S128FTG＋步進馬達＋24 V 電源產生

初始化時的 `MX_TIM4_Init()` 註解寫著「TIM4：預除頻到 1 MHz，CH4 → M1 的 STEP（D9）」，也就是 TIM4 的第 4 通道從 D9 送出 STEP。

**PWM 怎麼產生頻率**：計時器每 1 µs（1 MHz）加一，數到 ARR（自動重載值）就從 0 重來，所以一個週期是 ARR＋1 µs，頻率 ＝ 1 MHz ÷ (ARR＋1)。比較值設成 `arr / 2`，輸出前半個週期是高電位、後半是低電位，這叫「50% 責任週期」。每個上升緣就是一個 STEP。16 位元計時器的 ARR 最大 65535，最慢只能到 1 MHz ÷ 65536，大約 15 pps，所以比 16 pps 慢就直接停止輸出。

**速度與距離**：

```c
#define M1_MICROSTEP     16       // TB67 的 MODE2..0（100），要和驅動板的設定一樣
#define M1_STEPS_REV    (200 * M1_MICROSTEP)   // 1.8° 馬達：一圈 200 個全步 × 微步
#define M1_MAX_PPS     (M1_STEPS_REV * 2)   // 最高速度：每秒 2 圈（120 RPM）
#define M1_ACCEL       (M1_STEPS_REV * 4)   // 加速度：每秒增加 4 圈／秒 → 0.5 秒加到最高速
#define M1_MOVE        (M1_STEPS_REV * 2)   // 每次移動 2 圈
```

以 NUCLEO-H743ZI2＋TB67S128FTG＋步進馬達＋24 V 電源產生

- 1.8° 的馬達一圈是 200 個「全步」。驅動板設成 1/16 微步時，每個全步再分成 16 份，一圈要 200 × 16 ＝ 3200 個脈波。
- 轉速 RPM ＝ pps ÷ (全步數 × 微步) × 60。最高速度 3200 × 2 ＝ 6400 pps，6400 ÷ 3200 × 60 ＝ 120 RPM。這時 ARR ＝ 1000000 ÷ 6400 − 1，取整數是 155。
- `M1_MICROSTEP` 一定要和驅動板的 MODE 設定一樣，程式算出來的速度才對。

**梯形加減速**：轉子和負載有慣性，pps 不能一下子跳到最高；跳太快時轉子跟不上磁場，就會「失步」（少走好幾步，甚至停在原地嗡嗡叫）。所以 `M1_Update()` 每 10 ms 被呼叫一次，讓速度慢慢上升、到最高速維持、快到終點時再慢慢下降，畫成速度對時間的圖是梯形：

```c
static void M1_Update(void)
{
  if (m1Wait > 0) { m1Wait--; return; }                    // 到點後停一下
  float remain = M1_MOVE - m1Pos;                          // 還要走幾步
  float brake = m1Pps * m1Pps / (2.0f * M1_ACCEL);         // 從目前速度減到 0 要走的步數＝v²÷(2a)
  if (remain <= brake) m1Pps -= M1_ACCEL * 0.01f;          // 該減速了：每 10 ms 減少 a × 0.01 秒
  else if (m1Pps < M1_MAX_PPS) m1Pps += M1_ACCEL * 0.01f;  // 還沒到最高速：繼續加速
  if (m1Pps > M1_MAX_PPS) m1Pps = M1_MAX_PPS;
  if (m1Pps <= 0.0f || m1Pos >= M1_MOVE) {                 // 到了：停止、換方向、休息 0.5 秒
    M1_SetPps(0);
    m1Pps = 0.0f;
    m1Pos = 0.0f;
    m1Dir = !m1Dir;
    HAL_GPIO_WritePin(M1_DIR_Port, M1_DIR_Pin, (m1Dir) ? GPIO_PIN_SET : GPIO_PIN_RESET);
    m1Wait = 50;
    return;
  }
  M1_SetPps((uint32_t)m1Pps);
  m1Pos += m1Pps * 0.01f;                                  // 這 10 ms 送出的步數
}
```

以 NUCLEO-H743ZI2＋TB67S128FTG＋步進馬達＋24 V 電源產生

代入數字：加速度 a ＝ 3200 × 4 ＝ 12800 pps/s，每 10 ms 加 128 pps，0.5 秒加到 6400 pps。從 6400 pps 減到 0 要走 v² ÷ (2a) ＝ 6400² ÷ 25600 ＝ 1600 步（半圈），所以剩下的步數小於等於這個值時就開始減速。每次走 2 圈（6400 步），到了就停 0.5 秒（`m1Wait = 50` 圈）、換方向，再走回來。

**第二顆馬達 M2**：接兩組驅動板和馬達時，`M2_Update()` 讓 M2 連續轉動，速度每 10 ms 最多改變 `M2_ACCEL * 0.01f`，慢慢靠近目標值 `m2Target`（這就是 ramp，斜坡）。有旋鈕時，每 100 ms 用 ADC 讀值換算目標速度（`m2Target = (float)adc * M2_MAX_PPS / 4095.0f;`）；沒有旋鈕時每 3 秒切換快慢。

**STEP 要接哪一支腳**：116 種晶片裡有 108 種設定了兩組 STEP 輸出（NUCLEO-H743ZI2 是 D9 的 `TIM4_CH4` 和 D6 的 `TIM1_CH1`），「建議接線」會把 CLK 接到這兩支腳。MSP430FR2433、FR2311、FR6989 和 LPC800 系列沒有設定 STEP 輸出：在這些板子上，範例不會產生步進馬達的程式，檢測會出現「程式沒有控制 …（TB67 STBY）」這類警告，要自己寫。

**在模擬器裡會看到**：點 3D 畫面上的馬達打開「步進馬達示波器」：STEP、DIR、線圈 A／B 電流四個通道，下面是轉速曲線（加速段和減速段有底色）。「說明」分頁即時代入轉速公式；「手動測試」可以關掉加減速、加重負載，看看什麼時候會失步；「教學」有 9 個步驟。

**常見錯誤**：

- 一體式馬達套件的 CLK 接到一般 GPIO：「馬達套件 的 CLK 接到 D7（PF13）」。
- TB67S128FTG 的 CLK 接到一般 GPIO：「TB67 的 CLK 接到一般 GPIO（D7（PF13））」。這只是警告，用程式切換那支腳也能一步一步推動，但最快只有幾百 pps。
- CLK 接好了，程式卻沒有啟動 PWM：「程式沒有啟動計時器 PWM」。
- 在示波器裡把微步改成 1/64，程式還是 16：「說明」分頁會出現「程式以為是 1/16，模組設成 1/64」，同樣的 pps 只剩四分之一的速度。

**對應關卡**：闖關 6「TB67S128FTG 推動步進馬達」。

### 3.11 TB67S128FTG 步進馬達驅動板

步進馬達每一相要 1 到 2 A，而且電流要能正反兩個方向流，GPIO 只能輸出大約 20 mA，所以中間一定要有驅動板。驅動板右側接「大電流」（馬達電源和馬達），左側接 MCU 的「邏輯訊號」。範例用的是 CLK-IN 模式：MCU 只給 STEP 和方向，線圈電流怎麼切換由驅動 IC 自己處理。

程式為驅動板定義三支輸出腳 `M1_STBY`、`M1_EN`、`M1_DIR`，和一支輸入腳 `M1_FAULT`（註解寫「LO0／LO1 → D5（PE11）：錯誤旗標（低電位＝有錯誤）」）。開機時依序設定：

```c
  HAL_GPIO_WritePin(M1_STBY_Port, M1_STBY_Pin, GPIO_PIN_SET);   // TB67：離開待機（STANDBY 高電位）
  HAL_GPIO_WritePin(M1_EN_Port, M1_EN_Pin, GPIO_PIN_SET);   // TB67：打開輸出（ENABLE 高電位）
  HAL_GPIO_WritePin(M1_DIR_Port, M1_DIR_Pin, GPIO_PIN_SET);
```

以 NUCLEO-H743ZI2＋TB67S128FTG＋步進馬達＋24 V 電源產生

**每一支腳**（「建議接線」的接法）：

| 腳位 | 功能 | 建議接線接到 | 程式怎麼用 |
| --- | --- | --- | --- |
| GND | 邏輯地 | 電源軌 −（MCU 的 GND） | 一定要共地，訊號才有參考電位 |
| IOREF | 邏輯電位參考 | 電源軌 +（3V3） | LO0、LO1 會被上拉到這個電壓 |
| STBY | STANDBY，高電位工作 | GPIO | 開機設高電位；拉低再拉高可以清除錯誤 |
| EN | ENABLE，高電位送電給馬達 | GPIO | 開機設高電位 |
| RST | RESET，高電位時忽略 STEP | 不接 | 板上下拉，不接就是正常工作 |
| CLK | STEP，每個上升緣前進一個微步 | 計時器 PWM 腳 | `M1_SetPps()` |
| DIR | CW/CCW，高電位順時針 | GPIO | `M1_Update()` 到點時反轉 |
| MODE0 到 MODE2 | 微步設定 | 不接（用板上跳線，預設 1/16） | 要和 `M1_MICROSTEP` 一樣 |
| LO0、LO1 | 錯誤旗標，低電位＝有錯誤 | 兩支並接到同一支 GPIO | 每秒讀一次 |
| VIN、PGND | 馬達電源 6.5 到 44 V | 馬達電源的 V+、V− | 不能接 MCU 的電源 |
| VCC | 板上 5 V 輸出（約 5 mA） | 不接 | 只能拿來拉高邏輯腳 |
| A+、A−、B+、B− | 馬達兩組線圈 | 馬達的 A+、A−、B+、B− | 常見顏色：黑、綠、紅、藍 |

**為什麼 STBY、EN 一定要拉高**：驅動板上這些輸入腳都有下拉電阻，沒接線或沒有共地時都是低電位，也就是「待機」和「輸出關閉」，馬達不會動。範例依 STANDBY → ENABLE → 方向的順序設定。

**開汲極（open-drain）錯誤旗標**：LO0、LO1 是「開汲極」輸出：晶片只能把線拉到低電位，或是放開不管；放開時由上拉電阻（接到 IOREF）把線拉成高電位。因為沒有人主動輸出高電位，兩個開汲極輸出可以直接接在一起，任何一個拉低整條線就變低。所以「建議接線」把 LO0、LO1 並接到一支 GPIO，任何一種錯誤都讀得到。

| 錯誤 | 原因 | LO0 | LO1 |
| --- | --- | --- | --- |
| 過電流（ISD） | 馬達線短路，或一組線圈跨接在 A 和 B 之間 | 低 | 高 |
| 馬達斷線（OPD） | ENABLE 打開了但馬達沒接或某條線沒接好 | 高 | 低 |
| 過熱（TSD） | 電流限制（VREF）太高或沒有散熱片 | 低 | 低 |

**重設的順序**：錯誤發生後驅動板會「鎖住」，就算接線改好也不會自己恢復。要把 STANDBY 拉低再拉高，或關掉馬達電源再打開。範例每秒檢查一次：

```c
      if (!(HAL_GPIO_ReadPin(M1_FAULT_Port, M1_FAULT_Pin) == GPIO_PIN_SET)) {          // LO0／LO1 被拉低：驅動板偵測到錯誤（過電流、馬達斷線或過熱）
        printf("M1：TB67 回報錯誤，STANDBY 拉低再拉高來清除\r\n");
        HAL_GPIO_WritePin(M1_STBY_Port, M1_STBY_Pin, GPIO_PIN_RESET);
        HAL_Delay(1);
        HAL_GPIO_WritePin(M1_STBY_Port, M1_STBY_Pin, GPIO_PIN_SET);
      }
      printf("M1：%lu pps（%lu RPM）\r\n", (unsigned long)m1Pps, (unsigned long)(m1Pps * 60.0f / M1_STEPS_REV));
```

以 NUCLEO-H743ZI2＋TB67S128FTG＋步進馬達＋24 V 電源產生

如果原因還在（例如線圈還是接錯相），重設之後馬上又會出錯，所以序列埠會每秒印一次「回報錯誤」，直到你把接線改好。

**電流限制**：「元件」分頁點驅動板可以調 VREF，電流限制 I ＝ VREF × 1.56。超過馬達的額定電流馬達會過熱；沒有散熱片又超過約 2.1 A 時，晶片大約 20 秒就會過熱保護。

**在模擬器裡會看到**：「元件」分頁點驅動板，會出現接線圖（MCU、驅動板、馬達電源和馬達之間的每一條線，顏色代表對錯）和接線表（每一支腳的功能、應該接到哪裡、目前接到哪裡），接線一改就更新。點接線表的一列會在 3D 畫面標出那支腳。序列埠每秒印一次「M1：… pps（… RPM）」。

**常見錯誤**：

- 驅動板左側 GND 沒接 MCU：「TB67 沒有和 MCU 共地」。馬達電源的 V− 接在 PGND 不代表和 MCU 共地，MCU 的 GND 也要接過來。
- 馬達線接錯相：「馬達 的線圈接錯相」，觸發過電流保護，馬達只會抖。用三用電表量，兩條線之間有幾歐姆電阻的就是同一組線圈。
- STBY 沒接：「TB67 的 STBY 沒有接」；EN 沒接：「TB67 的 EN 沒有接」。
- RST 接到 3V3：「TB67 的 RST 接到 3V3」，STEP 全部被忽略。
- 用 5 V 的 USB 電源：「TB67 的 VIN 只有 5 V」，低電壓保護會關閉輸出。換成 12 V 或 24 V。
- 程式不讀錯誤旗標：「程式沒有讀取 PE11（TB67 的錯誤旗標）」。
- 邏輯腳碰到馬達電源（超過 5.5 V）會燒毀驅動板：「TB67 已經燒毀」；馬達電源碰到開發板，開發板會斷電。

**對應關卡**：闖關 6「TB67S128FTG 推動步進馬達」、故障挑戰 9「步進馬達完全不動」、故障挑戰 10「步進馬達只會抖」。

| 設定腳位方向 | `GPIOPinTypeGPIOOutput`、`GPIOPinTypeGPIOInput`（上拉加 `GPIOPadConfigSet`） | `GPIO_setPadConfig`、`GPIO_setDirectionMode` | `GPIO_PinInit`（`outConfig` 或 `inConfig`） |
| 輸出高／低 | `GPIOPinWrite`（寫入腳位遮罩或 0） | `GPIO_writePin`（1 或 0） | `GPIO_PinWrite`（`1U` 或 `0U`） |
| 切換 | `GPIOPinWrite` 寫入 `GPIOPinRead` 的結果 XOR 腳位遮罩 | `GPIO_togglePin` | `GPIO_PortToggle`（`1U << 腳號`） |
| 讀取 | `GPIOPinRead` 不等於 0 | `GPIO_readPin` 等於 1 | `GPIO_PinRead` 等於 `1U` |
| 延遲 10 ms | `SysCtlDelay(g_ui32SysClock / 3 / 100)` | `DEVICE_DELAY_US(10000)` | `SDK_DelayAtLeastUs(10000U, SDK_DEVICE_MAXIMUM_CPU_CLOCK_FREQUENCY)` |
| ADC | `ADCProcessorTrigger`、`ADCIntStatus`、`ADCIntClear`、`ADCSequenceDataGet` | `ADC_forceSOC`、`ADC_getInterruptStatus`、`ADC_clearInterruptStatus`、`ADC_readResult` | 依晶片：`ADC16_GetChannelConversionValue`、`LPADC_GetConvResult`、`ADC_GetChannelConversionResult`、`ADC_GetChannelConversionValue` |
| I2C | `I2CMasterSlaveAddrSet`、`I2CMasterDataPut`、`I2CMasterControl`、`I2CMasterDataGet`、`I2CMasterErr` | `I2C_setTargetAddress`、`I2C_setDataCount`、`I2C_putData`、`I2C_sendStartCondition`、`I2C_getData` | `I2C_MasterStart`、`I2C_MasterWriteBlocking`、`I2C_MasterReadBlocking`、`I2C_MasterStop`；LPI2C 的晶片用 `LPI2C_MasterStart`、`LPI2C_MasterSend`、`LPI2C_MasterReceive`、`LPI2C_MasterStop` |
| SPI | `SSIDataPut`、`SSIDataGet` | `SPI_writeDataBlockingNonFIFO`、`SPI_readDataBlockingNonFIFO` | 依晶片：`DSPI_MasterTransferBlocking`、`LPSPI_MasterTransferBlocking` 或 `SPI_MasterTransferBlocking` |
| 序列埠輸出 | `UARTprintf`（範例不用 `%f`） | `printf`（範例用 `%f`） | `PRINTF`（範例不用 `%f`） |
| CAN 送出 | `CANMessageSet` | `CAN_sendMessage` | `FLEXCAN_TransferSendBlocking` |
| STEP（PWM） | `PWMGenPeriodSet`、`PWMPulseWidthSet`、`PWMGenEnable` | `EPWM_setTimeBasePeriod`、`EPWM_setCounterCompareValue`、`EPWM_setTimeBaseCounterMode` | `FTM_SetupPwm`、`TPM_SetupPwm`、`CTIMER_SetupPwm` 或 `QTMR_SetupPwm`，再 `..._StartTimer` |

幾個值得注意的差異：

- **延遲**：HAL、C2000、MCUXpresso 直接給毫秒或微秒；MSPM0、MSP430 給「CPU 週期數」，所以範例會依晶片時脈算好，例如 80 MHz 的 MSPM0G3507 延遲 10 ms 是 `delay_cycles(800000)`；TivaWare 的 `SysCtlDelay` 每數一次要 3 個週期，所以要除以 3。
- **PWM 時脈**：HAL、MSPM0、MSP430 的範例把計時器時脈設成 1 MHz；TivaWare 是系統時脈 ÷ 64；C2000 是 1.25 MHz；NXP 的函式直接給頻率（Hz）。
- **C2000 用 16 位元存位元組**：C28x 的最小資料單位是 16 位元，所以 C2000 的範例把所有位元組陣列宣告成 `uint16_t`（其他 SDK 是 `uint8_t`），SPI 送出時還要左移 8 位元（程式註解寫著「8 位元模式：要送出的資料必須靠左對齊」）。

## 5. 模擬器支援的 C 語法

模擬器不是真的交叉編譯器：它先用規則檢查常見錯誤（訊息格式和 gcc 一樣），再把 C 程式轉成 JavaScript 執行。範例程式用到的語法都沒問題；自己寫程式時，下面這些是用模擬器的編譯器實際測試的結果。

### 可以用

| 類別 | 說明 |
| --- | --- |
| 流程控制 | `if`、`else`、`for`、`while`、`do`…`while`、`switch`／`case`、`break`、`continue`、三元運算 `? :` |
| 運算 | 四則運算、`%`、位元運算、移位、`+=`、`<<=` 這類複合指定 |
| 資料 | 整數型別（`uint8_t` 到 `uint32_t`、`int`、`char`）、`float`、`bool`、一維陣列（可以給初值）、`char` 陣列字串 |
| 函式 | 自己寫函式、`static` 函式、全域變數與檔案層級的 `static` 變數；陣列參數（`uint8_t *buf`）用 `buf[i]` 存取 |
| 前置處理 | `#define` 常數和帶參數的巨集 |
| 轉型 | 對變數或括號運算式做整數轉型會截斷，例如 `(int16_t)v`、`(uint8_t)(a << 4)` |
| 輸出 | `printf`、`sprintf`、`strlen`、`abs`、`sqrt`；格式支援 `%d %u %x %X %f %e %g %c %s %p`，含寬度、精度、補零 |

### 不支援（編譯時出現「無法解析的語法」）

- `struct`、`union`、`typedef`、`enum`
- 二維陣列
- 指標解參考 `*p` 和指標運算 `p++`

SDK 本身的結構變數可以用，例如範例裡的 `canTx.Identifier = CAN_TX_ID;`；不能用的是「自己宣告新的結構」。

### 和真的 C 不一樣的地方

| 寫法 | 模擬器 | 真的 C | 建議寫法 |
| --- | --- | --- | --- |
| `int a = 7 / 2;` 之後算 `a * 2` | 7（除法沒有捨去小數） | 6 | `(int)(a / b)` |
| `uint8_t c = 250;` 之後 `c = c + 10;` | 260（不會自動溢位） | 4 | `(uint8_t)(c + 10)` |
| `(int16_t)40000` | 40000（對常數直接轉型不會截斷） | -25536 | 先存進變數再轉型 |
| 函式裡的 `static int k = 0;` | 每次呼叫都重新變回 0 | 保留上一次的值 | 改成檔案層級的 `static` 變數 |

範例程式裡的 `tick / 100` 用 `%u` 印出，`printf` 會取整數，所以不受第一點影響；計時器的 ARR 也會在寫進計時器時取整數。

### 編譯與執行時的訊息

- `expected ';' before 'printf'`：上一行少了分號。
- `implicit declaration of function 'foo'；模擬器不支援這個函式`：函式沒有定義，或模擬器沒有實作。
- `'某函式' 是 SDK 的設定函式，模擬器沒有實作，執行時會略過`：這是警告，不影響燒錄。時脈、腳位多工這類設定函式都屬於這種。
- `'hi2c4' undeclared (first use in this function)；模擬器支援 hi2c1–3、hspi1–3、huart1–3、hlpuart1、hadc1、hcan1–2、hfdcan1–2`：用了模擬器沒有的 handle。要注意 HAL 的 I2C 實際只接了 `hi2c1`。
- `` undefined reference to `main' ``：沒有 `main` 函式。
- `主迴圈沒有 HAL_Delay，序列埠輸出會非常密集`：`while (1)` 裡沒有任何延遲函式。
- 執行中序列埠出現「HardFault：使用了未宣告的變數：…」：用了沒有宣告的變數名稱，程式會停下來。

## 6. 常見錯誤速查

下表的檢測訊息是在 NUCLEO-H743ZI2 上實際產生的，換了板子腳位名稱會不同。

| 症狀 | 原因 | 「檢測」分頁的訊息 | 怎麼修 |
| --- | --- | --- | --- |
| 板載 LED 在閃，外接 LED 不亮 | LED 的 GND 沒接 | 「LED 的 GND 沒有接地」 | GND 接排針 GND 或電源軌 − |
| 外接 LED 不亮，檢測只有警告 | SIG 接的腳不是程式控制的腳 | 「程式沒有控制 PF13」 | 照 `#define` 註解改接，或重新載入範例 |
| 按住按鈕沒反應 | OUT 接到別的腳 | 「程式沒有讀取 PG9」 | 接到 `#define BTN` 那支腳 |
| 旋鈕轉到三分之二就卡在最大值 | 旋鈕 VCC 接 5V | 「類比（10 kΩ 旋轉電位器） 的 VCC 接到 5 V」 | VCC 改接 3V3 |
| ADC 讀不到電壓 | OUT 接到沒有 ADC 的腳 | 「類比 OUT 接到 D7（PF13）」 | 改接 A0 到 A5 |
| 序列埠印「讀取失敗」 | SCL、SDA 接反 | 「感測器 的 SCL 與 SDA 接反」 | 兩條線對調 |
| 序列埠印「沒有回應」，檢測全過 | 程式裡的 I2C 位址寫錯 | 沒有訊息 | `TEMP_ADDR` 改成元件規格上的位址 |
| 兩顆感測器資料錯亂 | 位址相同 | 「I2C 位址衝突：0x48」 | 換成位址不同的型號 |
| 感測器壞掉 | 3.6 V 的元件接到 5V | 「感測器（BME280 溫溼度／氣壓） 的 VCC 接到 5 V」 | 改接 3V3，再換一顆新的 |
| 繼電器有指示燈但不吸合 | 5 V 繼電器接 3.3 V | 「繼電器（5 V 繼電器模組） 的 VCC 只有 3.3 V」 | 改接 5V，或換 3 V 繼電器 |
| Flash 讀出來全是 FF | DI、DO 接反 | 「Flash 的 DI 與 DO 接反」 | DI 接 MOSI、DO 接 MISO |
| 沒辦法單獨選中 SPI 元件 | CS 接到 SCK、MISO 或 MOSI | 「熱電偶 的 CS 接到 SPI 訊號腳」 | CS 接一支獨立的 GPIO |
| CAN 只有送出、沒有收到 | TXD、RXD 接反 | 「CAN 的 TXD 與 RXD 接反」 | TXD 接 `CAN_TX`、RXD 接 `CAN_RX` |
| TJA1050 完全不動 | 接 3.3 V | 「CAN（TJA1050 CAN 收發器） 的 VCC 只有 3.3 V」 | 改接 5V，或換 SN65HVD230 |
| 驅動板有電，馬達不動 | 驅動板沒有和 MCU 共地 | 「TB67 沒有和 MCU 共地」 | 左側 GND 接 MCU 的 GND |
| 馬達不動 | STANDBY 沒接 | 「TB67 的 STBY 沒有接」 | STBY 接 GPIO，程式設高電位 |
| 馬達不動 | 用 5 V USB 電源 | 「TB67 的 VIN 只有 5 V」 | 換 12 V 或 24 V 電源 |
| 馬達只會抖，序列埠每秒印「回報錯誤」 | 線圈接錯相 | 「馬達 的線圈接錯相」 | 同一組線圈接到同一相 |
| 馬達轉得很慢 | CLK 接一般 GPIO | 「TB67 的 CLK 接到一般 GPIO（D7（PF13））」 | 改接計時器 PWM 腳 |
| 馬達不轉，接線都對 | 程式沒有啟動 PWM | 「程式沒有啟動計時器 PWM」 | 重新載入範例看寫法 |
| 序列埠輸出被干擾 | 模組接到序列埠腳 | 「PD8 是虛擬序列埠腳位」 | 改接其他腳 |
| 分析儀波形亂跳、解碼失敗 | 分析儀沒有共地 | 「UART 分析 的 GND 沒有接」 | 分析儀 GND 接開發板 GND |
| 元件接好了但完全沒有通訊 | 程式沒有呼叫對應的函式 | 「程式沒有使用 I2C」（SPI、CAN 也一樣） | 載入範例程式 |
| 模組是灰色、不會動 | 這塊板子沒有 SPI、CAN 或 STEP 輸出 | 自己接了線時：「CAN（SN65HVD230 CAN 收發器） 在 NUCLEO-F401RE 上不能用」 | 照提示換成有這個功能的開發板（這個例子提示 NUCLEO-F446RE 或 NUCLEO-F429ZI） |

另外兩個常見的情況：

- **改了接線，程式就停了**：這是正常的。硬體一變更，模擬器就會停止程式並標示「需重新燒錄」，要重新檢測、編譯、燒錄。
- **檢測只有「警告」**：警告不擋燒錄，但通常代表程式和接線對不起來。最快的確認方法是按「載入範例程式」，比對 `#define` 註解和實際接線。

## 7. 下一步

右上角「闖關學習」有兩種關卡，每一步都依模擬器的實際狀態自動打勾。

**闖關課程**（程式已經寫好，你要讀懂程式、自己接線、完成任務）：

1. 點亮外接 LED：GPIO 輸出、共地（本文 3.1）
2. 按鈕控制蜂鳴器：GPIO 輸入 → 判斷 → 輸出（3.2、3.3）
3. 旋鈕和 ADC：類比轉數位、3.3 V 上限（3.5）
4. I2C 溫度感測器：兩條線、位址、讀暫存器（3.6）
5. 用邏輯分析儀看 UART：起始位元、鮑率（3.7）
6. TB67S128FTG 推動步進馬達：馬達電源、共地、STEP／DIR（3.10、3.11）

**故障挑戰**（程式已經燒好在跑，但有地方錯了；看症狀、找原因、修好，再重新檢測、編譯、燒錄）：

- 1「LED 不會亮」、2「按鈕按了沒反應」：3.1、3.2
- 3「旋鈕轉到一半就卡住」：3.5
- 4「溫度讀取失敗（接線）」、5「溫度讀取失敗（程式）」：3.6
- 6「繼電器吸不動」：3.4
- 7「Flash 讀出來全是 FF」：3.8
- 8「CAN 沒有回應」：3.9
- 9「步進馬達完全不動」、10「步進馬達只會抖」：3.10、3.11

幾個小提醒：

- 不看提示過關 3 顆星，看了提示 2 顆星，看了解答 1 顆星。闖關時按「建議接線」最多 2 顆星；故障挑戰用了「建議接線」或「載入範例程式」等於看解答，記 1 顆星。
- 需要 SPI、CAN 或 STEP 輸出的關卡，如果目前的開發板沒有這個功能，會改用預設的 NUCLEO-H743ZI2。
